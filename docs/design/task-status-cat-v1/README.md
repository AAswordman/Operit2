# Operit 任务状态猫：插件建议与动画素材 v1

2026-11-21。此目录是可播放的设计提案和美术素材，尚未注册或实现 Operit 插件。

## 直接查看

打开 [index.html](index.html)，可切换六种状态、重新播放、调整显示大小、切换底色并演示任务流程。页面和卡片直接复用同一套动画，可直接以本地文件打开。

原图是 **720 × 704、48 帧、12 fps、4 秒、无限循环的透明 APNG**。按用户要求，仓库不再保存原图副本、序列帧图集、独立静态预览或另一种动画格式。

续画使用内置 ImageGen；生成源图是 1536 × 1024、6 列 × 4 行、24 个 256 × 256 关键帧。源图留在 Codex 的生成目录，**不复制到仓库或插件包**。打包在内存中裁切、编排时间，并输出无损透明动画 WebP；未通过代码重画、补画或修饰像素。

播放以 12 fps 为时间基准，WebP 用 83/84 ms 交替表示帧边界，整秒时长保持准确。编码器将重复的停留帧合并为较长曝光，避免重复存储整帧。`playbackTicks` 表示 12 fps 时间格数，`encodedFrames` 表示实际编码帧数，两者并不等同。

| 状态 | 文件 | 播放长度 | 动作与用途 |
| --- | --- | --- | --- |
| 运行 | [working.webp](animations/working.webp) | 96 格 / 8 秒循环 | 打字 2 秒 → 思考 2 秒 → 打字 2 秒 → 停顿 2 秒 |
| 思考 | [thinking.webp](animations/thinking.webp) | 48 格 / 4 秒循环 | 托腮、抬眼、眨眼，用于等待模型/连接 |
| 等待批准 | [approval.webp](animations/approval.webp) | 96 格 / 8 秒循环 | 停下打字、抬爪看向用户，琥珀色提示 |
| 完成 | [completed.webp](animations/completed.webp) | 36 格 / 3 秒，单次 | 开心伸懒腰、绿色勾，随后由状态机进入 idle |
| 空闲 | [idle.webp](animations/idle.webp) | 96 格 / 8 秒循环 | 爪子休息、轻呼吸、慢眨眼 |

**最终美术资产只有 `animations/*.webp` 六个文件，合计 8,391,682 字节（约 8.0 MiB）**。动画属性和体积记录在 [manifest.json](manifest.json)。没有对应的 PNG、图集或缩略图副本。

此版属于生成式美术续画初稿：保留蓝猫、发光青眼、深色电脑和右侧卷尾的视觉特征。生成画面与原图的像素密度、局部比例不完全一致，**原图与续画没有拼接成同一条动画**；运行状态的 8 秒来自续画素材组合。正式接入前建议确认小尺寸观感与动作衔接。

## 插件边界

建议新增独立、可停用的 `task_status_pet` 插件，插件拥有外观、状态映射、设置和窗口声明；宿主继续拥有系统窗口、权限和平台能力。

使用仓库已有的接口：

- `ToolPkg.registerAppLifecycleHook`：处理 `application_on_background`、`application_on_foreground`，使“后台显示、返回应用收起”成为明确的产品选项。
- `ToolPkg.registerChatRuntimeHook`：接收 `state_changed`，按 `chatId` 与 `slot` 记录状态。载荷含 `state`、`isActive`、`activeChatIds`、`activeConversationCount`、`toolName` 和可选进度。
- `ToolPkg.registerToolPermissionHook`：接收 `requests_changed`，使用类型化待审批请求表示等待状态，不分析自然语言或日志。
- `ToolPkg.ui.floatingWindows.set("task-status", ...)`：固定一个窗口 ID，由宿主管理创建、更新和关闭。设置页显式查询 `capabilities()` 并由用户点击请求系统悬浮授权。
- Compose 路由承载猫与任务摘要。动画在窗口渲染侧播放；状态变化才更新插件 UI，不让 JS 每 83 ms 向宿主发送消息。

接口依据：[悬浮窗文档](../../../plugins/docs/FLOATING_WINDOWS.md)、[插件类型](../../../plugins/types/toolpkg.d.ts)、[工具权限文档](../../../plugins/docs/TOOL_PERMISSIONS.md)。实际仓库代码是能力事实来源。

### 状态与交互

1. 只显示一只猫。多个任务使用数量角标；点击打开任务列表或当前最需要处理的任务。
2. 待批准请求优先于其他任务的普通状态。批准操作在对应的审批界面完成，猫本身只提示和导航。
3. 确实阻塞的异常排在待批准之后。普通运行时，`connecting` 可用 thinking；`receiving`、`executing_tool`、`tool_progress` 等映射 working。取消不应被当成成功；原始错误详情由任务界面呈现。
4. 无其他活跃任务时，成功完成才播放 completed，播放一次后进入 idle。其他任务还在运行时保留运行状态，以短摘要提示已完成数量。
5. 默认 128 × 128 逻辑像素、不抢焦点、可拖动；点击与拖动由宿主区分。透明区目前不代表逐像素输入穿透，窗口矩形应紧凑。
6. 工具名/进度可显示简短提示；不凭空生成百分比。桌宠默认不展示任务正文，展开摘要再查看。
7. 用户在设置中选择“后台有任务时显示”“完成后继续待命”和“始终显示”。锁屏、不可见时暂停绘制。动画帧率和后台任务存活是两件事，悬浮窗本身不提供保活服务。

### 仍需核查的实现点

- 插件刚启用和从后台返回时需要一份权威任务快照，而不只依赖后续事件。现有 runtime hook 载荷可报告活跃 ID 和数量，但不能据此声称能还原每个任务的完整历史状态。实施时核查现有查询接口，需要时补充通用快照契约。
- 核对应用生命周期 hook 在各宿主的实际分发，以及主引擎后台存活与独立窗口的生命周期。当前悬浮包明确要求拥有者引擎存活。
- 确认插件渲染器对动画 WebP、单次播放和隐藏窗口暂停的支持。此目录只提供一套动画素材，不表示 Flutter 插件链路已验证。
- 处理插件停用、进程退出、任务取消、审批被其他界面解决、并行任务完成，以及运行期间再次出现审批的状态转换。

## 各平台的当前范围

“全平台使用同一个插件”和“所有平台都能在其他应用上方显示”是不同的要求。以 `capabilities().scope` 的报告为准，插件设置页应直接显示实际能力范围。

| 平台 | 当前仓库能力 | 对后台跨应用需求的含义 |
| --- | --- | --- |
| Windows | 系统悬浮接口 | 可以按此实现，需要设备验证透明、置顶和后台行为 |
| macOS | 系统悬浮接口 | 文档记录已有原生生命周期检查，仍需验证本插件 |
| Android | `TYPE_APPLICATION_OVERLAY` | 需要用户授予悬浮权限；后台存活需要单独核实 |
| Linux X11 | RGBA 系统窗口 | 需要合成器，需设备验证 |
| Linux Wayland | 应用内悬浮 | 当前接口不能满足后台跨应用显示 |
| iOS | 应用内悬浮 | 普通应用不能借插件得到任意跨应用悬浮窗；可另行设计系统允许的任务提醒呈现 |
| OpenHarmony | 应用内悬浮 | 系统悬浮涉及受限权限、签名和宿主窗口适配，当前尚未实现 |
| Web | 应用视图内悬浮 | 浏览器标签后台时无法用此接口显示系统桌宠 |

当前不为能力不足的平台实现额外呈现策略。若用户决定增加通知、实时活动等呈现，它们应作为明确产品能力单独设计和适配。
