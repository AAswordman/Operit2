# Core / Edge 通信协议版本

Core 与 Edge 共用一个整数协议版本。软件发布版本（例如 `2.0.0-preview.17`）、
厂商固件版本和协议版本各自独立。运行时只比较协议版本：相同就继续配对、重连、
路由和同步；不同则返回明确的协议不兼容错误。软件版本仍用于展示，不参与兼容判断。

## 构建时的协议指纹

`core/peer-protocol.json` 是协议版本及 SHA-256 指纹的唯一记录。构建扫描
`core/crates/runtime/application/src`，仅提取带 `operit_core_route` 注解的方法：

- 方法签名：方法名、参数名与类型、返回类型和泛型等签名信息。
- 路由元数据：目标类型及路由地址、binding、call/watch/push 类型、生命周期、
  权限、创建规则和反向流元素类型。

提取结果排序并按固定格式编码后计算指纹，生成的 Rust 分发代码本身不参与哈希。
扫描源码是为了定位路由声明，文件完整内容并不参与指纹。函数体、普通注释、文档、
格式、未注解的方法（包括 `sync*` 方法）、无关 DTO、类型别名及自定义编解码实现的
改动均不会触发协议版本更新。路由注解参数的排列顺序也不影响指纹。

旧的 `sources` 全文扫描与 `schemaRoots` 泛类型扫描已经移除。v23 是切换至路由
签名规则的首次记录，v1–v22 的历史 hash 保持原样；后续只有上述路由契约变化才会
触发自动版本检查。签名中引用类型的内部字段以及底层报文格式不自动展开扫描，
这类修改若破坏互通，需要开发者主动评估并调整协议契约和版本。

Hash 仅供构建和开发检查使用，不随握手、同步请求或设备资料发送，运行时也不比较。

v24 将认证会话分块格式的显式修订标识 `operit-peer-session-fragments-v1` 纳入指纹。
这不是源码全文哈希；普通实现调整仍不改变协议版本。今后修改不兼容的会话报文格式时，
必须更新该标识并追加版本记录。v24 端点要求对端同为 v24；原有身份和配对凭据保留。

## 认证会话透明分块

`maxMessageBytes` 继续限制一条物理 Link 报文，不再作为认证后的逻辑消息大小上限。
hello 声明本端帧上限，认证 transcript 同时绑定双方帧上限，双向使用较小值。
会话层扣除外层 Link 信封、长度字段、16 字节分块头和 AEAD tag 后选择有效负载大小，
每块有效负载最多 64 KiB，适用于现有 TCP、HTTP、WebSocket、串口和蓝牙载体。

每块仍通过同一个 `$peer.session/data` 认证信封发送。加密明文的前 16 字节依次为
大端 u64 的完整消息字节数、当前块偏移，其后为这一块的逻辑消息字节。头和内容一起
接受 AEAD 认证；nonce 逐块递增。单条逻辑消息以及既有 reply batch 持有同一有序写锁，
不会与其他业务消息交错。接收端检查长度、偏移、认证和顺序，只在收齐后向 Call、Watch、
Push 分发完整的原始逻辑消息，上层接口不感知分块。

部分接收状态跨 receive future 取消保留，断线或认证失败后释放，不交付半条消息。
内存按已接收的数据增长，不按对端声明的总长度预分配；完整消息仍需能放入接收端内存。
物理分块的认证接收及成功写入均计入通道活动，持续传输不会仅因尚未重组完成而触发心跳超时。
本机制不建立额外连接，不自动重试或断点续传；网络中断仍向调用方报告失败。

修改流程：

1. 修改协议相关源码，运行正常的 Cargo 构建或检查。
2. 如果指纹变化，构建会失败，并打印新的 SHA-256。
3. 在 `revisions` 末尾追加记录，将 `version` 递增并填写新 hash。历史记录保持原样。
4. 再次构建并执行 Core / Edge 互通回归。发布软件时无需再额外递增协议版本。

示例（hash 应填写构建实际给出的 64 位小写十六进制值）：

```json
"revisions": [
  { "version": 1, "hash": "<已发布的 hash>" },
  { "version": 2, "hash": "<新协议的 hash>" }
]
```

Cargo 构建检查路由契约指纹与当前记录一致；CI 还会将版本记录与 PR / push 的基线
比较，拒绝覆盖历史 hash、回退版本或不递增版本的修改。可在本地运行：

```sh
python3 tools/check_peer_protocol.py --base HEAD
cargo check --manifest-path core/Cargo.toml -p operit-node-runtime --no-default-features --features peer-runtime
```

## 运行时检查

- 新配对与已有凭据重连都声明协议版本；版本纳入认证 transcript。
- 空间投影协商声明同一协议版本，供 Core 与 Edge 准入及控制同步使用。
- 业务同步通过 `$node.sync` 的 `protocol` 方法读取最终目标的协议版本，适用于中继路由。
- 拓扑状态比较设备资料中的 `protocolVersion`；Edge 无需伪造 Core 软件版本。
- 协议版本不匹配返回 `PEER_PROTOCOL_MISMATCH`；缺少协议声明返回
  `PEER_PROTOCOL_UPGRADE_REQUIRED`。旧资料仍能反序列化，未声明版本显示未知，
  不会根据软件版本推断协议版本。

这是首次引入统一协议版本。此前未声明该版本的 Core 或 Edge 程序需要升级一次；
已有设备身份和配对凭据保留。此后软件版本变化、协议版本不变时，不要求厂商同步升级。
原有配对安全协议、投影分页协议和同步记录格式的内部版本继续保留，其修改也纳入总指纹。
