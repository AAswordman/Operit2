## 后续正文消失

09:08:11.938 开始输出 `write_file` 的原生工具调用；09:08:14.950，DeepSeek 流出现 connection aborted 并重试。09:08:12.280 后消息可见正文停在 199 字符，直至 09:10:10 正常结束。期间工具仍在执行，最终一轮没有工具调用，提供方统计正文 2372 字节。

生产代码的确存在协议丢失：DeepSeek 包装器恢复自己的 DSML decoder 保存点，却用只承载字符串的 `FnStream` 交给下游；`collect_ordered` 不会从独立 event channel 重新合并修订事件。下游因此保留断流前的半截工具标签，后续正文进入未完成工具块。

新增回归测试通过生产父流包装器及 `AssistantMarkupStreamState` 重放“半截工具标签 → 回滚 → 完整工具调用 → 工具结果 → 最终正文”：修复前最终可见文本为空，修复后为预期正文。历史提交 `10e2aa10d` 引入 DSML 流包装时已经包含此错误。

同类审查发现 OpenAI Responses 的包装器也通过只承载字符串的 collection 丢失修订事件。本次提取公共的有序冷流包装器，同时修复 DeepSeek 和 Responses。Claude/Gemini 的对应字符串包装用于非流式结果，没有相同的父流重试修订转发链路。

后续全链路审查发现摘要生成同样使用纯文字拼接，开启重试后会混入失败尝试；摘要和标题现统一通过有序最终正文收集入口处理。插件提供方的文字共享适配器原本只订阅实时尾部，丢失订阅前缓存的输出，现直接使用上游的回放与实时收集。删除无调用的字符流包装、双通道共享适配器和旧的纯文字收集函数。链路与边界详见 [model-stream-revisions.md](model-stream-revisions.md)。

## 命令与交互链路调整

后续将 Super Admin 的单次命令与常驻交互拆开：`terminal` / SDK `run` 每次启动新进程，完整脚本在进程启动前传入；`terminal_open` / SDK `open` 保留原始交互 shell。两者复用 Host PTY、输入与屏幕能力。新命令按真实进程退出收取结果，不再等待提示符或将脚本输入给交互行编辑器。前台等待到期只交还控制权，运行中的会话继续由 Host 持有。

输入操作在复制 writer 后释放会话注册表锁，文本和 Enter 使用一次写入；屏幕渲染也在复制缓冲后释放锁。Termux 与浏览器 guest relay 分别观察子进程退出和输出 EOF，避免后台后代持有输出通道时永远无法完成。已完成的插件会话按十分钟空闲策略回收，活着的交互 shell 需主动关闭。完整的各平台实现、输出收尾上限和验证范围见 [terminal-command-execution.md](terminal-command-execution.md)。这些调整消除了明确的协议等待与锁占用问题；仍未在最初反馈设备上复现并定位全部停顿原因。
