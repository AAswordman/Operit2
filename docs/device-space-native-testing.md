## 最新版双向报协议身份缺失：排查与改动

用户报告两端均为最新版，发现设备后不出配对码，二维码能解析但确认后无动作，
切换 TCP / HTTP / WebSocket 无效。按用户回忆的英文，可能对应源码中的
`PEER_PROTOCOL_UPGRADE_REQUIRED`，但尚无错误原文确认。该分支检查消息中的 `protocol` 是否缺失；
它与 `PEER_PROTOCOL_MISMATCH`（明确收到不同版本号）不同。
不能仅凭该错误断定用户没有升级，也尚未复现用户另一环境的这次故障。

源码中 outbound Hello、inbound HelloReply 的 transcript 都主动写入当前协议。
新增生产握手的二进制 Link 编码回归测试：双向平台信息都能完成 hello/authorize，
接收端生成配对码；缺少身份字段时按请求、回复分别拒绝并保留具体错误阶段。
这证明当前本地编码路径正常，不证明发布安装包或用户实际运行环境一定正常。

已修改：

- 缺少身份字段的文案不再直接归因为“请升级固件”；保留严格的协议校验，
  在错误文案和 details 里补上收到请求／收到回复／空间协商阶段及本机协议版本。
- 已用失败回归测试证实网络配对原来没有等待上限，现为探测与建连各 10 秒、
  单次未加密握手交换 5 秒、整段握手或确认 20 秒；串口原有重试保留。
- 对不返回的连接，确保有错误返回、关闭已建立的 carrier，且不发布配对凭据。
- 添加设备窗口在等待时显示“正在连接”，失败时恢复操作，并记录发起方式与错误。
  被配对码或加入弹窗覆盖时停止背景连接动画。
- 当时按仓库构建要求追加开发中的协议修订 v14，既有 v1–v13 保持不变；
  当时构建互测两端一起使用 v14。当前提交的协议记录见下方集成说明。

验证：原生 pairing 相关 36 项通过（包含实际 TCP / HTTP / WebSocket、二维码、
新增 4 项等待上限和 2 项二进制握手测试），协议校验与构建保护 6 项通过；
Flutter 的设备操作、二维码、空间加入共 57 项通过；改动 Dart 文件静态检查通过。
macOS debug 与 iOS simulator debug 原生构建均成功。
