# 聊天附件的位置与生命周期

## 保存位置与共享

已绑定工作区的聊天把新选择的小附件直接保存到主工作区的
`.operit/attachments/<attachmentId>/<规范化文件名>`。没有工作区时保存到固定产出区域
`/operitapp/outputs/<父对话创建时间>/.operit/attachments/...`；外部挂载工作区的附件也使用该应用管理的产出区域。物理位置是 `runtime/data/chat_outputs/<父对话创建时间>`。

新导入附件在 Rust 统一入口生成跨平台文件名：合法且不超过 180 UTF-8 字节的文件名保持原样；包含 Windows 禁用字符、设备保留名、末尾空格或句点，或超长的名称改为 `attachment.<扩展名>`，无可用扩展名时使用 `attachment`。每个附件拥有独立 UUID 目录，因此回退名称相同不会覆盖其他附件。写入路径和返回的 `fileName` 使用同一个规范化结果，定位文件保留 `.operit-ref.json` 后缀；外部原件的真实定位路径保持原样。路径穿越、分隔符和控制字符仍按原有规则拒绝。此规则仅作用于新导入，不扫描或迁移历史附件。

文件同步在所有平台统一排除不兼容名称：任一文件名或目录名包含禁用字符、设备保留名、末尾空格/句点，或超过 255 UTF-8 字节时，整个路径不纳入同步范围。扫描不上传，接收不下载或写入；已有同步记录与待写入状态也直接忽略。本地原文件和消息引用保持原样，不生成删除通知，不做历史改名或引用迁移。

产出目录绑定独立持久化并随 Space 同步，子孙对话和消息分支继承已保存的绑定，不按当前日期重建。提升子对话或删除父对话不改变路径，创建时间相同允许共享目录。这个产出区域不是用户工作区。工作区与产出目录都使用 `.operit/sync.json` 控制复制，详见 `workspace-file-sync.md`。

上传前先读取策略，默认单文件 16 MiB、目录自动同步总量 256 MiB。大文件有持久来源时，不复制原件，只保存 `<规范化文件名>.operit-ref.json`，包含来源 `nodeId`、准确 VFS `path`、文件名与大小。Android 仅在持久 URI 授权成功后提供来源描述；macOS 保存安全作用域书签，iOS 文件选择器保留文件授权。临时 picker token 只能用于本次有界读取，不能作为长期定位地址。

没有持久来源的输入（例如浏览器 Blob、临时媒体或无法持久授权的 URI）在来源节点一次性保存到 `runtime/data/attachment_sources/<uploadId>/<规范化文件名>`，再在聊天目录保存定位文件。该源目录归 CoreNode 所有，不自动同步。已知大小在读取前检查，超过配置的总量上限时拒绝导入；未知大小在读取过程中执行上限。未知大小即使最终很小也使用这条来源保存路径。这里没有设备全局磁盘配额。

文件选择、粘贴图片、CLI 文件附件和插件上传共用附件导入服务，按上述策略直接保存本体或定位文件到 `.operit/attachments/`。注册附件只接受已提交到当前聊天附件目录且节点、VFS 与本机位置一致的结果；不再接受临时目录或任意本机路径。旧上传、完成、丢弃和搬运接口及旧目录创建方法已删除。CLI 不再自行读取整份文本或维护另一套 MIME 与大小判断。历史 `runtime/data/chat_attachments/<chatId>/<attachmentId>/<原文件名>` 继续读取，名称兼容时参与同步，不再作为新附件落点。正式文件不因聊天删除、输入移除或发送完成而自动回收，因为分支、变体和历史消息可能继续引用。未提交的写入会丢弃；已有文件不自动 GC，不迁移旧文件。

## 路径、节点与读取

- `AttachmentInfo.nodeId` 保留导入来源节点。发送、接收和执行节点切换不覆盖它。
- `vfsPath` 和历史附件标签保存稳定的共享或来源 VFS 地址；真正组装模型请求时，`path` 与文件型 `id` 按当前对话文件目录换算成相对路径，不改写持久化消息。`filePath` 仅供本机预览和媒体处理，不发送给 AI 猜测其他设备的物理路径。
- 优先使用消息已内嵌的内容。需要文件时先用给出的相对路径检查当前节点；小文件可能已经同步，可直接使用本机副本。切换工作区后，历史附件从保存的稳定地址重新换算相对路径。来源信息不保证文件已传输。
- 本机缺失时检查 `list_core_nodes`，文件工具可以用来源节点限定的 VFS 路径。需要终端时，在准确来源节点继续执行，并使用该 Host 返回的所选终端路径。外部挂载不因聊天共享而复制。
- 来源离线时提示重连或重新上传，不搜索其他设备的无关目录。无 `path` 时使用内嵌内容或请求重新上传，无 `node_id` 的旧附件保持来源未知。
- Markdown 与思考文本的消息 part 保存 `file_base_path`、`file_node_id`。历史图片和文件链接按保存时的目录解析，后续工作区切换、消息编辑不能替换其原基准。相对路径支持 `..`；越出当前文件目录的 VFS 相对路径不保证与终端的物理目录布局一致，需要终端时使用所选 Host 解析的路径。已指定协议、节点或绝对 VFS 地址保留原含义。

界面在无工作区时提供“对话产出”文件入口，展示真实保存位置并复用文件浏览器。附件预览保留节点与 VFS 位置，支持复制文件位置；图片和媒体通过现有 VFS 文件读取接口访问本体，本机副本缺失时按记录的来源节点读取。手动终端与 AI 终端使用 Core 返回的同一持久目录，不在界面重算目录名。

VFS 的 `/operitapp/data` 映射整个 Runtime 根，因此旧地址
`/operitapp/data/data/chat_attachments/...` 中有两层 `data`。新附件使用工作区或产出区域的地址。
旧消息引用的已清理 `temp/clean_on_exit` 文件无法恢复，需要重新上传。

## 文件选择与有界导入

- app 通过统一 `SelectedFileInput` 消费元数据和输入流。实现复用现有 `OperitFolderAccessPlatform` 注册、`file_selector` 和原生选择通道；app/core 不判断 Android、Apple、Windows 或 Web，也不调用平台授权通道或按平台拼来源。
- Android 适配器返回 token、名称、MIME、可选大小与成功持久授权的来源；元数据和读取在后台线程执行，不预读整文件。Web 保留浏览器 `File/Blob`，读取时仅转换最多 1 MiB 的切片。
- Android 的“附加图片”使用 `ACTION_GET_CONTENT`（`image/*`、`CATEGORY_OPENABLE`、允许多选），通过系统应用选择面板选择图库或其他图片提供者，不指定厂商包名。它不再使用可能自动转入 DocumentsUI 的 AndroidX 照片选择合约。普通文件和快照仍使用 `ACTION_OPEN_DOCUMENT`；图片提供者返回的临时 URI 按现有有界导入流程读取，不假定具有持久授权。提供者是否支持多选由其实现决定。此路径需在出现问题的 HarmonyOS 4.2 设备上验收：选择图库后能够返回图片并生成附件，取消选择后能够再次打开。
- OpenHarmony 选择器返回 URI 和元数据，延迟打开原生描述符，每次最多读取 1 MiB，结束、取消、失败或插件解绑时关闭；不先复制选择文件到缓存。原生文件选择通过范围读取，不在 Dart 中预读整文件。
- 聊天与快照共用有界输入 owner，每块最多 1 MiB，上传方等待当前块写入完成后再读取下一块。快照选择和资源释放复用已有选择器接口。
- 小附件 reverse stream 通过 `RuntimeStorageWriteSession` 直接写最终目录，不额外复制归档。流长度与声明长度必须匹配，且客户端只有完整成功读取后才发送完成标记；取消、截断和异常关闭不能提交部分文件，空文件同样需要完整完成。
- 持久来源注册发生在文件实际所在的本机 Host，聊天接收节点只保存定位或最终小文件，避免把客户端路径误解释为远端节点的本地路径。

## 消息区附件展示

附件标签既承载真实文件，也承载已经内嵌的上下文；展示方式不能只看扩展名，
也不能只对某个插件名做特殊处理。气泡与命令行聊天共用以下规则：

| 内容 | 默认展示 | 查看方式 |
| --- | --- | --- |
| 插件注入的内嵌文本/JSON/XML、时间天气等设备信息、通知、位置、屏幕文字、粘贴文本 | 消息底部的低对比“补充信息”入口，点开查看 | 点击查看完整可选择文本，并可复制 |
| 工具包、技能与 `@工作区` 引用的内嵌内容 | 同一补充信息入口，详情保留包名或引用路径 | 同上 |
| 文档、代码文件、压缩包及其他真实文件 | 保持原来的 72×72 文件缩略卡与气泡堆叠展示 | 点击进入文件预览 |
| 图片 | 保持原来的缩略图与气泡堆叠展示 | 点击图片缩放预览 |
| 音频、视频 | 保持原来的媒体附件卡片 | 点击播放预览 |

客户端以 MIME、媒体池类型、文件来源和内嵌内容共同判断：有非空内嵌文本、
文本/结构化文本 MIME 且使用合成 ID 的附件按上下文展示；有真实路径或媒体池来源
的附件仍按文件/媒体展示。`workspace_mention:` 和 `package_attach:` 是内嵌引用，
即使后缀包含路径也使用紧凑展示。插件通过现有 `type: text` 选择器结果提交的信息
自然适用此规则，通过已提交上传返回的 `type: file` 则保持文件展示，无需逐插件适配。
已有 `workspace_context` 系统上下文仍由消息解析器隐藏，不新增可见卡片。
真实文件和媒体卡片的尺寸、样式及堆叠交互保持原样。
内嵌上下文不进入附件区、不参与卡片堆叠；只在消息正文下方显示一个无底色、无边框、
无图标的低对比“补充信息”入口，常规字号下高度约 14。数量增加只更新计数，
不增加默认占用；点击后才显示各项详情及复制操作。

这只改变消息区展示与查看交互，不改变附件标签、注入正文、发给模型的内容或持久化位置。

## 终端与相对路径执行上下文

`super_admin` 经由 JavaScript SDK 创建或复用终端时，使用该次调用保留的原生对话上下文；
Promise 续执行不得改用引擎默认上下文。终端进入与文件工具一致的当前目录 `.` 后才返回会话，
绑定工作区时使用主目录，解绑后恢复父子对话固定的产出目录。缺少目录绑定或进入目录失败时，
终止调用，不回退到主目录执行用户命令。

系统提示和 `super_admin` 的说明都要求直接使用附件给出的相对路径，不再要求无工作区时
从 `/`、主目录或全盘搜索定位已知附件。任务明确需要其他挂载时，再使用现有 VFS 和 Host 路径解析能力。
