# 通用 IP 网络设备发现

本实现不读取 VPN API、CLI、设备名单或专用地址段。网络需要允许目录访问和最终的设备连接；共同目录是跨网首次发现的引导信息，留空配置不会凭空发现远端陌生设备。

## 使用

- **目录节点**：在现有连接设置的高级选项中，留空目录地址，设置一个组密钥及目录监听端口（默认 `37196`）。只有该角色开放额外 HTTP 入口。目录绑定使用现有监听地址的 IP；不需要额外选择网卡。
- **普通节点**：填写同一目录地址（例如 `http://<可达 IP>:37196`）和组密钥。客户端使用 URL 中的端口，本机的目录监听端口不参与查询。普通节点不开放额外发现服务。
- **被发现的设备**：开启原有“允许被搜索”及网络接收。后台任务自动登记当前实际监听地址；仅浏览的客户端发送空登记，目录节点本身也可以只提供目录而不发布业务地址。
- 清空目录地址和密钥可关闭目录功能，局域网 mDNS 与原有配对保留。目录配置和监听配置通过原有 `localHostConfig` / `saveLocalHostConfig` 一次读写。

内置目录使用 HTTP，客户端支持 HTTPS 目录或反向代理。组凭据应放在可信 LAN/VPN 链路上或通过 HTTPS 访问。目录不是业务中继，组密钥不能替代配对、会话认证或 Space 授权。

## 数据流与代码归属

`Host ServiceDiscovery / 通用目录 → peer/discovery.rs → 发现列表及配对/重连候选 → 原有认证流程`。

- `peer/discovery.rs` 统一管理发现状态、来源刷新、部分失败、候选过滤和租约缓存。手动扫描和既有 availability worker 调用同一个入口。Host 的 mDNS 快照并非撤回事件，因此沿用原有 LAN 缓存语义；目录记录按单调时钟过期。
- `peer/directory.rs` 只负责目录登记、查询及服务端登记租约。服务端登记表与本机查询缓存分开，查询结果不能作为新登记转发续命。HTTP、socket、计时及任务执行仍由 Host 提供。
- 二维码和目录公告共用当前实际监听器的地址生成逻辑。公告最多包含 8 个网络 endpoint，不从已保存配置猜业务端口。
- 首次配对和已配对重连共用候选拨号、限时认证及失败连接关闭逻辑。身份和会话密钥验证成功后，沿用原有唯一端点更新入口；不新增配对地址历史，也不逐台猜固定端口。
- 目录续租复用现有后台 worker，刷新间隔最多每 15 秒一次、单次预算 3 秒。扫描对话框打开期间每 5 秒刷新一次（后台扫描预算 3 秒），保留正在进行的扫描和配对互斥，关闭后停止刷新。晚到的登记自动出现在列表；目录租约过期后不再作为候选。

## 协议和资源

`POST /operit/discovery/v1`，使用组密钥派生的 HMAC bearer 凭据。请求为本机公告或仅浏览时的 JSON `null`；响应为当前有效公告列表。其他方法不提供匿名设备信息。

公告包含 `version`、`nodeId`、`displayName`、`endpoints` 和 `ttlMs`。租约最长 45 秒，转发时携带剩余时间。目录最多保存 63 个远端登记，加上自身最多返回 64 条；本机缓存最多保存 64 个目录节点。请求上限 4 KiB，响应上限 64 KiB；取消或超时关闭 HTTP 流。切换目录配置清除旧目录线索。

配置目录服务器却无法绑定时，启动返回错误并回滚本次新开的业务监听，不会报告配置成功。停止监听释放目录入口、后台任务及发现缓存。

## 验证范围

测试覆盖无组播目录查询、自动后台登记、租约到期、配置切换、错误密钥、非法及超大数据、目录端口释放和冲突、目录缓存不回流、发现不改变配对凭据、认证后更新端点以及首次配对地址回退。保留原 mDNS 重连、订阅恢复、并发解绑与凭据替换回归；Flutter 覆盖单次配置保存、晚到记录更新及关闭后停止刷新。
