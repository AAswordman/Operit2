# Core 托管的 Edge 空间入口方案

状态：托管授权仍是设计方案；第一阶段的版本协商、有界权限导出和报文预检已接入代码。
现有固件仍使用本地空间控制记录，尚未切换到 Core 托管授权。
本文描述受限 Edge 的目标职责、迁移顺序和验收边界，不表示 ESP32 已完成修复。

## 已接入的迁移前置协议

当前实现通过既有直连、已配对的 `node.space` Call 协商 `projectionProtocol`，
请求携带 `version: 1`。回复绑定被调用的节点身份，声明实际连接报文上限、是否为
endpoint、是否支持逐条快照导出，以及可选的 `projectionReference` 能力。旧回复省略该字段时按不支持处理。当前唯一支持的 `authorityMode` 是 `localReplay`；
不能把它解释为入口授权，也不声明支持 `coreManaged`。

| 方法 | 当前行为 |
| --- | --- |
| `projectionProtocol` | 检查显式版本；未知版本、错误节点和无效回复明确失败 |
| `snapshotHeader` | 只在 endpoint 提供成员、资料、拓扑、退出凭据，以及权限记录数和摘要；不是完整策略 |
| `snapshotControlPage` | 按不可变操作 ID 返回一条权限记录或结束标记，绑定空间、摘要和上一条 ID |
| `observeSpaceProjection` | 只在协商支持且双方完整权限记录相同时回传资料和拓扑，绑定 endpoint 当前权限摘要；不导入权限、不跨空间、不确认退出回执 |
| `node.space.control/exchangeBounded` | 调用方声明版本及接收上限；接收方仍按现有策略验证控制操作，限制完整回复大小 |

权限导出从 endpoint 的已编码持久投影逐条读取，不创建完整 `Vec<SyncOperation>`，
也不调用会发布 preference outbox 的日志查询接口。现有权限重放同样改为只读已提交
控制日志，配对与权限检查不再顺带发布业务 preference。尚未退役的旧同步文件会使导出失败，
不会被默默忽略。摘要覆盖原始记录和未知 payload 字段，记录变化或未知游标要求重新导出。

Core 对直连 endpoint 的普通投影同步和可达成员同步均采用这条逐条读取路径，
后者不再重复要求 endpoint 返回完整权限日志。收齐后，再取一次头部并检查整份
清单一致性；通过现有完整权限校验后才能导入。Core 收集最多 4096 条记录，拒绝重复、
乱序、缺失、多余记录和提前结束。完整 Core 之间继续使用原快照协议；经中继到达的 Core 不要求建立额外直连配对来协商。

当双方完整权限记录逐项相等（包括不可变信封和未知 payload 字段），且同空间、双方均无待处理退出回执时，
Core 使用 `observeSpaceProjection`，不再把同一批权限历史发回 Edge 解码。
Edge 在写入前复核本地权限摘要、完整资料和成员授权；摘要过期要求重新导出，不自动放宽为无界快照。
权限记录不同、跨空间、存在退出回执或旧端未声明能力时仍走原来的完整快照与授权校验。
这仅减少重复同步的接收工作集，新权限历史和首次加入仍有原有内存限制，不属于 Core 托管授权。

Core 在投影回传和同空间控制交换两处发送入口检查对端声明的上限，检查包括实际路由
身份长度，并为会话封装预留 1024 字节。endpoint 的普通入口、预编码快照/控制入口和
旧式完整导出也进行预检。预编码入口跳过外层路由头，权限操作逐条解码后转换为记录，
避免完整 JSON 元数据树与本地权限记录同时驻留。完整策略验证后，受限 endpoint 会先
逐条收拢收到的权限记录，再读取本地 NVS；持久导入时只展开当前一条。超限返回 `SPACE_MESSAGE_LIMIT`，不截断权限记录来凑大小。
预期的版本、导出和超限错误使用短错误码，不附带 Core 的完整回溯，避免错误回复本身超限。
这限制的是空间同步报文，尚不是聊天、配置和审批全链路的统一上限协商。

只有旧端精确返回未知空间方法，才允许继续旧的 `localReplay` 协议。鉴权失败、超时、
报文错误、身份不符和未知版本不触发降级。受限设备的加入后控制交换要求支持
`exchangeBounded`；旧 Core 不支持时明确报错，不重试无界回复。

这一步减少迁移导出时的工作集，并阻止已协商的超大空间报文进入设备。
它**尚未取消 Edge 的本地权限重放和持久历史**，也未实现入口选择、会话授权、
可恢复的权威移交确认、审批委托或旧缓存退役。真机结论仅覆盖下文明确测过的场景。

## 目标与职责

完整 Core 保存空间成员、拓扑、角色定义、权限操作历史和审批协调状态，
执行全空间的权限计算与同步。Edge 通过明确选择且已授权的直连 Core 进入空间，
不再为了显示连接状态、交换设备配置或使用聊天而重放完整权限历史。

| 数据或操作 | Core | Edge |
| --- | --- | --- |
| 完整空间成员、拓扑、权限历史及审计 | 保存、计算和同步 | 不复制，不承担空间路由 |
| 本机身份、配对密钥、Wi-Fi、设备配置 | 不接管设备私有凭据 | 本机保存 |
| 入口选择 | 校验该设备当前资格 | 保存本机明确接受的 Core 身份和空间范围 |
| 当前会话授权 | 根据当前策略计算、更新和撤销 | 只保留与本机和所选入口有关的有界结果 |
| 加入审批 | 保存申请、分配审批、提交权限变更和恢复事务 | 显示分配给本机的申请，保存必要的确认/重试状态 |
| 聊天、Binding、Agent 与 ToolPkg | 按现有业务 owner 处理 | 使用现有调用与有界显示窗口 |
| 网络接收缓冲 | 按协商上限发包 | 必须保留有界接收缓冲，不能移到远端 |

这里将入口 Core 纳入 Edge 的授权信任边界。配对本身不产生入口授权；
不得通过“遇到任意同空间 Core 就信任”替代本机认可和既有成员准入。
入口 Core 不因托管状态而获得超出当前空间策略的设备操作权限。

## 当前依赖及改动位置

当前 `spaceChannelScope` 从 `NetworkControlStore.currentState` 物化本地策略，
`SessionSpaceClient` 在每次使用入口时检查它。仅删掉 ESP32 的权限文件会破坏这一边界。

当前 `SpacePersistenceSyncService.exchangePairedDeviceSpaceProjection` 对声明分页能力的
endpoint 先读取 `snapshotHeader` 和逐条权限页，复核最终清单后再导入；仅精确识别到旧版
未知方法时回退到完整 `snapshot`。Core 在双方完整权限相同且无退出回执时使用绑定摘要的
`observeSpaceProjection`；其余情况仍向 Edge 发送经过报文大小预检的完整 `observeSpaceSnapshot`。可达成员同步也复用这条分页路径，避免再次请求完整控制日志，
但 Edge 仍须校验和持久化完整权限记录，配置同步和审批恢复也仍依赖本地策略。
只改固件显示层无法取消这份工作。

需要共同修改以下入口，并保留完整 Core 之间的现有协议：

- Core 同步调度：识别受限 Edge，使用专用的入口状态交换，避免向它发送完整快照和控制批次。
- 共享 Peer runtime：将入口资格绑定到已认证的直连会话，统一检查 Call、Watch、Push 及已有订阅。
- Edge 空间服务：使用有界入口状态，保存本机确认和重试状态，停止加载完整成员及策略历史。
- Core 审批服务：保留协调与权限提交；Edge 只提交明确的审批决定，不自行生成完整空间策略。
- 本地退出、解除配对和入口切换：清理对应入口授权、等待中的调用和订阅，保留设备身份及配置的空间隔离。

## 能力协商与报文边界

沿用共享 Link、配对与加密会话，不新建设备 token 或旁路信任通道。
双方显式协商入口协议版本和最大接收报文；版本不兼容时返回明确错误。
旧 Core 的完整快照不能被当作受限协议的静默回退。

入口状态交换只携带目标 Edge、本次直连 Core、空间范围、授权版本、会话挑战和本机所需的
有限资格。不得夹带其他成员名单、完整角色库或权限操作历史。
配置和审批消息也必须计入报文上限；单条过大时在解码大对象之前拒绝，
或通过明确的有界分段协议传输。接收缓冲仍在 Edge 上，峰值由协商上限约束。

持久入口选择和当前有效授权分开：选择可跨重启保存，当前会话授权不能跨连接恢复后直接使用。
授权至少绑定协议版本、Edge 身份、Core 身份、空间标识和本次认证会话。
版本及挑战值的产生、序列化和校验需要由共享协议统一定义，不能仅靠两个节点的墙钟比较。

## 授权、撤销和恢复

1. 本机先确认入口选择；Core 从当前权威策略验证双方资格，不能以配对记录替代空间授权。
2. Edge 只接受来自所选、已配对 Core 的直接认证响应，校验目标、空间、本次挑战与授权版本。
3. Call、Watch、Push 及回调统一使用本次有效入口，不能仅在首次打开聊天时检查。
4. 撤销、隔离、空间变化、入口切换或解除配对使旧授权失效，并关闭对应订阅和输入会话。
   旧连接的迟到响应不能恢复已失效的入口。
5. 断连时立即停止远端操作。重新连接或重启后先重新取得当前授权，再恢复可恢复的订阅。
   发送消息、创建聊天、审批决定及硬件动作不能因重连自动重复执行。
6. Core 的变更通知用于及时失效；会话授权还须有明确的失效/续期规则，不能把一次认证永久缓存。
   当前分布式策略的传播边界仍需保留，不能声称离线节点能即时知道远端撤销。
7. Core 不可用时，本机原生功能和空间隔离内的独立聊天继续按现有配置工作，
   新的远端空间操作明确报告入口不可用。

## 审批与最后一个 Core 离开

本机用户的审批确认仍留在 Edge；Core 负责校验审批分配版本、幂等提交和持久化结果。
Edge 不缓存全量申请列表或完整源空间快照。审批重试必须关联原申请和原决定，
不能把网络超时转换为自动同意，也不能用迟到的结果覆盖新分配。

当前 Edge 还能作为独立空间的审批网关。这种模式与托管入口不同，必须显式处理：

- 首次还没有入口 Core 时，本机初始化与首次加入的信任建立不能依赖一个尚不存在的 Core。
- 已托管后，只有新的 Core 与 Edge 直接配对，并不意味着入口 Core 已认可该申请。
  新协议必须定义网关转交及源身份校验，或者明确要求经 Core 网关申请；不能冒用 Edge 身份提交他人的申请。
- 最后一个托管 Core 退出、解除配对或被移除时，设备不能凭空重建已删除的完整权限历史，
  也不能把最后一次入口授权当成继续管理空间的权限。
- 切换托管 Core 前，必须完成完整权威资料与未完成审批的移交。没有可验证的接管结果时停止远端操作，
  保留原身份、原空间及恢复信息，不能自动退出或创建新空间。
- 用户明确执行本机退出时仍使用独立的退出流程，不由一次连接错误代替该确认。

首次引导、审批网关转交和最后一个 Core 的恢复协议都属于切换实现的前置条件，
不能在这些路径未实现时先删除设备上的原控制状态。

## 迁移顺序

1. 先实现并测试双方的能力协商、有界消息和新授权语义，保留原始持久状态。
2. 完整 Core 导入并持久保存 Edge 现有的权限历史及未完成审批。确认采用了相同空间和权限版本，
   验证重启后仍可恢复，再写入可重试的移交确认。
3. Edge 保存绑定所选 Core 和空间的移交记录，切换到受限入口协议。
   写入失败或任一步重启必须能明确判断继续哪一模式，不发布半套状态。
4. 完成切换后才精确退役已移交的空间控制缓存，保留身份、配对、设备配置和必要的审批恢复状态。
   不恢复旧 NVS，不整片擦除，不丢弃未知业务记录。
5. 旧 Core、未知协议版本和未完成移交保持明确的兼容性状态，不触发反复加载全量快照。

## 必须完成的验收

- 只有配对、没有准入/入口确认时，无法取得空间使用资格。
- 伪造 Core、错误 Edge/空间/会话、旧授权版本和旧配对世代均被拒绝。
- 撤销、隔离、入口切换、解除配对及重启使旧 Call/Watch/Push 授权和迟到响应失效。
- 初次加入、本机审批、审批重试、网关转交和最后一个 Core 离开均有可恢复行为。
- 在每一个持久写入边界注入失败或重启；原身份、原空间和未完成同意不丢失。
- 增加无关成员或控制历史不会增加 Edge 入口状态和普通消息的大小，
  超限消息在分配全量对象前返回错误。
- 完整 Core 之间的同步、权限历史和业务复制回归通过。
- ESP32 真机完成新的加入/审批/退出流程、重启恢复以及 UI 与网络并发测试，
  记录最低可用堆、最大连续空闲块和 NVS 占用。

协议实现和这些测试通过前，不能将文档中的目标写成现有固件的能力或硬件验收结论。
