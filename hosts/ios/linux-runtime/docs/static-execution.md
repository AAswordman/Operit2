# 静态 ARM64 汇编执行器

生产入口是 `ExecutionEngine::run()`，由每个 vCPU 独立持有。Linux 仍装载 rootfs 中的 ELF、动态库和任意版本的 Node/Python；宿主没有内置这些语言运行时。运行期间只生成普通数据记录，执行目标均来自构建时链接的 ARM64 汇编。

## 编译与执行

```text
ELF / 客体内存
  → decoder → 唯一指令构图 → BasicBlock / CFG
  → 常量传播、死值删除、标志活跃性
  → 统一驻留 ABI → 静态操作选择 / 融合
  → static_executor.S → 内部边 / 跨图桥接
  → 预算、系统调用、故障、映射/代码失效边界
```

`block_graph.cpp` 先发现唯一 PC，再按入口和控制流目标切块。回边引用已有块，不复制循环体。单图发现最多 16384 条指令、64 个代码页；基本块仅在控制流边界切分。直接调用保留目标和返回后的控制流；间接分支由守卫及冷解析器确定目标。

`optimizer.cpp` 保留每条原始指令供短预算和精确恢复使用。常量求值仅处理合法、无访存的整数语义；死写只能跨越已知纯操作，不能越过潜在故障或控制边界。被删除操作的退休数并入后续记录。已移除无后端消费者的 CFG 活跃性、循环 SCC 和整图 Top-K 分配。默认路径仍是块内优化。可选的 SSA 值编号、全局 CSE 和受守卫的加载调度见下文；它们默认关闭，不应将此执行器描述为通用机器码优化编译器。

`static_lowering.cpp` 选择普通整数、移位/扩展准备、位域、条件选择、普通标量/向量访存、标量双精度 FP、GP/SIMD 位搬运、浮点立即数、无符号整数到双精度转换、直接/间接控制流等静态执行单元。比较立即数和条件分支可融合为一个单元，仍退休两条客体指令。成对 GP/向量访存（含前后索引）同样使用原生单元；其余复杂寻址、结构访存、原子操作及其余 SIMD/FP 形式使用原语义实现。

## 执行 ABI

| 宿主位置 | 含义 |
|---|---|
| x3 | 固定驻留 guest X30，进出 C++ 时使用其 shadow home |
| x4 | 指向代码 epoch 的指针 |
| x6 | 当前基本块开始时的退休指令数 |
| x7 | 串行私有页稀疏索引根，不能使用时为空 |
| x8 | 低 63 位为块命中计数，bit 63 为私有的 FP-active 状态 |
| x19–x24 | 固定驻留 guest X0、X1、X2、X19、X20、SP |
| q8–q15 | 固定驻留 guest V0–V7 |
| x25 | 客体 NZCV，保持宿主原生的 bits 31:28 |
| x26 | 本次调用已经退休的客体指令数 |
| x27 | `ExecutionFrame` |
| x28 | 当前 32 字节操作记录 |
| x0–x2、x9–x17、q0–q4 | 私有临时值、分派、无故障准备和代码行比较 |

热操作记录为 32B：入口地址、64 位立即数、三个 16 位操作数、16 位冷索引和 64 位目标/附加字段。每操作另有 16B 冷记录，保存原始节点、元数据与精确退休前缀；总 payload 仍为 48B。冷索引只用于寻址元数据，不能当作退休计数。控制边在空闲操作数字段保存热退休前缀，普通 handler 不读取冷记录。Bridge/PIC 把冷记录内联于其 plan 中，保留 guard 字段偏移。诊断快照在图存活时复制解析后的值，回收后不访问原节点。

不使用 x18。入口保存宿主 x19–x30、完整 q8–q15 和 FPCR/FPSR，退出恢复。`executor_abi.h` 与 C++ 的 `offsetof` 断言覆盖执行帧、记录、桥接和翻译条目。栈保持 16 字节对齐，汇编入口包含 CFI。

静态汇编不能用数据中的整数任意选择宿主寄存器。`superoperators.def` 和 Python 构建生成器提供有限的操作数变体；实际 lowering 在编译时选定 handler 地址。移位/扩展和乘累加可以使用 x15 中的无架构副作用准备值，准备和消费之间没有 helper、故障或预算出口。已驻留的整数、普通加载目的和标量 FP 操作直接使用角色寄存器。24 种有界移位/扩展准备形式在 lowering 时选择，执行时只读取移位量，不再解释操作类型。没有运行时机器码编码、可执行页分配或按程序版本生成宿主二进制。

## 状态驻留与链接

所有图共享同一个驻留 ABI，选取前三个参数寄存器、前两个被调用者保存寄存器、SP、链接寄存器 X30 和八个 SIMD 参数寄存器；其他架构寄存器通过 shadow 访问。图内和跨图均不重新分配角色，直接边只改变操作游标。每个 handler 尾部拥有自己的间接分派位置，并提前读取下一记录的入口；条件分支的未跳转路径直接消费其显式 Next 边，省去一次边 handler 分派。间接边使用每边 32 组、四路、最多 128 个实际目标的有界缓存，命中后跳到图内块或跨图桥接；不按程序身份选择目标。

跨图链接持有 `BridgePlan`：先检查缓存代次，再读取目标代码 epoch 和观察作用域。代次必须先检查，防止读取已回收图的指针。统一驻留使跨图无需保存、重载或换位；旧 GP/SIMD 转移单元、前驱偏好和每图角色表已删除。不调用 C++，也不导出调用方的 `CpuState`。直接边只有一个可更新的桥接计划；间接边的桥接计划随 128 个目标槽固定上限分配，槽满后轮换替换。每图按页聚合所需代码行证明。新的文件观察周期中，桥接可在汇编里验证当前 epoch、证明代次及全部所需行位图；重用其他图已经建立的证明后直接进入目标图。证明尚未建立时，先尝试由汇编 leaf 比较已有驻留文件代码页。该能力由 PageAccess 发布，必须同时匹配代码和映射 epoch、当前文件观察代次及文件范围，并按相同 writer admission 规则取得 PageMutex 读锁。只比较尚未证明的所需 64B 行。观测缺失、页锁争用或字节变化时复用通用慢路径重新校验。正常证明路径不导出源图架构状态。文件页仍按所需跨度及 64 字节行检查；整页提前比较的方案在配对测量中退步，未保留。

缓存图拥有内部操作和外连桥接。淘汰/替换图之前递增缓存代次，使所有指向旧图的桥接失效。每次 `run()` 检查地址空间身份和可选函数替换的清单代次。缓存不以短预算作为键，也没有两个入口值的特殊桥接 ABI。

`ExecutionFrame::shadow` 是完整架构 home，七个 GP / 八个向量角色是其可恢复缓存。前六个 GP 使用 frame 前缀，X30 在每次进入 C++ 前直接保存到 shadow，返回汇编时重新加载。未驻留的值直接使用各自 home，不按 SSA 节点数分配槽。冷语义调用按读写效果发布所需状态，之后只重载声明的写集；部分复杂指令使用保守写集。对外返回时导出完整架构状态。

## 预算、故障和浮点环境

区域入口按 PC 有序块的剩余指令数预留前向路径预算；前向内部边直接进入块体，回边和外部入口重新检查。串行代码 epoch 检查合并到区域入口，并行执行仍逐块检查。外层调度批次由 4096 增至 262144 条。预算不足时按原始指令执行当前块短尾，不建立新的编译版本。融合和死值删除只在整块预算充足时生效。原生操作不逐条递增退休计数；块出口以块起始计数加原始指令前缀结算。故障或 helper 前按该操作前的原始前缀恢复精确计数，失败指令不退休；无架构副作用的准备操作不单独退休。

访存慢路径将 PC 置于实际客体指令。语义异常被 `noexcept` 的 C 入口捕获，先通过汇编正常恢复宿主上下文，再在 C++ 边界重抛；C++ 异常不跨汇编分派栈展开。整数和位搬运路径保持宿主浮点环境，仅在首次原生浮点算术前安装 guest FPCR/FPSR。激活后的控制可跨多个执行单元驻留；进入 C++ 时合并客体累计 FPSR 并恢复宿主环境，回来后再次执行 FP 算术时才重新激活。最终返回恢复宿主入口的完整 FPCR/FPSR，私有 active 标志不进入公开块计数。

串行私有页使用 8192 槽直接索引缓存，每槽 32 字节，保存读/写完整页标签、宿主地址偏差和 reservation 指针。页号异或高位后选槽；有效标签须为地址空间内的页基址，地址减标签的无符号差值须不大于 `4096 - 访问大小`，同时证明标签、权限和页内范围。空标签为 UINT64_MAX，以低位检查拒绝，避免极端地址误命中。每次执行入口、映射失效、COW 替换和进入并行模式清空缓存；原生 TLB 回退完成校验后补槽，冲突只增加回退。私有文件副本首次访问仍验证当前范围的文件大小，随后复用至本次执行结束；物理文件页逐次获取并释放 PageMutex 共享锁。双路 TLB 回退仍检查 tag、映射代次、serial permissions 和必要的文件观察代次。需要 COW 的写入、共享访问、文件底层写入、可执行页写入、跨页和并行访问使用同步内存路径。成功的私有原生写入清除独占 reservation token。宿主指针偏差仅在映射读取保护及当前执行范围内有效。

访存权限、页内范围、页索引、文件观测与页锁检查合并为读写 × 六种大小的 12 个静态叶入口，所有 handler 共用。正常成功访问只增加 BL/RET，不逐站点重复展开完整检查主体。

代码依赖保留共享的不可变页快照，并验证覆盖跨度；epoch 在整图校验结束时统一复核。文件代码须在新的观察范围重新检查，不能只比较全局 epoch。推测发现的后继若失去执行权限，会先从当前必需 PC 重构，延迟至真实进入后继时再触发取指故障。

## 验证与限制

`OPERIT_EXECUTION_DIAGNOSTICS` 构建开关默认为 OFF。开启时可分别统计 native proof 成功与 C++ fallback 次数，并保存 32B 热流/16B 冷元数据解析快照；诊断和采样计时不用于性能验收。

`arm64-execution` 包含高地址 Call 与冷记录前缀恢复、独立语义对照、随机精确前缀、真实回边、跨图不同 GP/SIMD 工作集与全架构状态恢复、缓存回收、32 个轮换间接目标、文件桥接代码行证明复用、自修改代码、外部 pwrite/mmap、跨页文件证明、截断、权限、COW、reservation、TLB 冲突、普通/成对向量访存矩阵、成对访问跨页故障，以及 FP 位模式/控制/异常。`arm64-isa-audit` 直接使用 ARM64 硬件作为另一条对照路径。

这仍然是静态优化执行器：操作记录之间存在间接分派，未覆盖的形式仍调用语义 helper。整数热循环的结果不能代表 Python、Node 或并行负载；最新构建、回归与配对测量见 [交付状态](delivery-status.md)。

## 可选的 SSA / CSE 与加载调度实验

`OPERIT_ARM64_GLOBAL_VALUES` 和 `OPERIT_ARM64_MEMORY_SCHEDULING` 是两个独立的 CMake 开关，均默认 OFF。仅改变 native `build_graph` 路径；Wasm 的 `build_instruction_graph` 继续使用原来的块内优化。实测与限制见 [2026-11-08 实验](performance/2026-11-08-global-values.md)。

`global_values.cpp` 给 GP/SP 和 NZCV 建立 SSA 定义与汇合 phi 输入，做有界的等价类固定点、常量传播和公共表达式值编号。先做无入口依赖的块内处理，再做跨块处理；只把仍在架构寄存器中的等价值变成全宽复制，或消除结果已经相同的写入。不会为 SSA 临时值分配运行时槽，不删除故障点，不对内存做 CSE。保守处理未精确描述的 helper 效果；BL 的推测返回边不能携带调用前事实。分析限于最多 1024 条指令、256 块，固定点最多 16 轮；超限保留原有块内路径。

只要实际应用了跨块事实，该图仅向外部缓存公开根入口；内部直接边仍可使用优化代码，中间 PC 的外部或间接进入重新构建以该 PC 为根的图。短预算继续执行原始节点，调用方在时间片间修改寄存器不会继承旧假设。这一入口限制和额外图分析都有实际成本。

加载调度只覆盖同一基址、相邻地址的独立普通 32/64 位整数加载，可提前第二次加载跨过最多三条无故障整数操作，再用一条宿主 LDP 完成两次读取。依赖检查也包含 CSE 新引入的复制源。执行前守卫要求串行私有页、权限及完整页内范围；冷缓存可通过普通原生 TLB 路径补充，再重新验证私有页能力。持有文件页锁的情况释放锁后回退。共享/并行、跨页、无法证明的情况按原顺序执行原始后缀，保留第一次读取、中间算术、第二次故障的精确状态与退休数。没有做 store 重排、跨故障点的无守卫提前读取或循环外内存提升。
