# 2026-11-06：静态汇编执行器替换与实测

本轮删除工作区原有的 C++ region/kernel 执行层，生产入口改为 `ExecutionEngine` 和构建时生成的 ARM64 汇编。Linux 继续从 rootfs 装载客体 ELF、动态库及 Node/Python；没有嵌入语言运行时，没有运行时宿主机器码生成。**原始 Python 热循环仍约 2.33 秒，0.5 秒目标未达到。**

## 对照方法

控制组是本轮重写前工作区的 C++ region 后端快照，不是仓库 HEAD 的早期解释器。为消除构建差异，两组均重新构建为 macOS ARM64 Release，`-O3 -DNDEBUG -flto=thin -arch arm64`，部署目标均使用空的 CMake 默认值。同一 Apple Clang、rootfs、CLI 参数和原始 Python 源码，每种设置交替运行三对，第二对倒序。每次新建进程；测量期间不运行构建、CTest 或采样。

`benchmarks/python_loop.py` 未修改，SHA256 为 `736118e90c7989f0352d26bce340ef3118a4efcf7d6b465ba4a71a99849e5eec`。每次 checksum 均为 `1267865`，指令预算为 2,000,000,000。CLI 未指定 CPU 数，两个版本均报告 `execution_threads=4`、`maximum_parallel_tasks=1`。命令将原始文件内容作为 `/usr/bin/python3 -B -c` 的参数，不改变循环次数或数学表达式。

完整进程时间由宿主 `perf_counter` 包围进程调用测得；循环内部时间由原始客体程序输出；峰值 RSS 来自 `/usr/bin/time -l`，包含图缓存、编译分配及宿主内存，区别于 VM 的客体 resident_bytes。各指标独立取中位数，不是一次运行的完整轨迹。

| 固定函数加速 | 指标 | 原 region | 静态汇编 |
|---|---|---:|---:|
| 关闭，默认行为 | Python 循环 | 2.550325 s | 2.333802 s |
| 关闭 | 完整进程 | 6.623871 s | 4.026016 s |
| 关闭 | 宿主峰值 RSS | 3,004,334,080 B | 318,554,112 B |
| 开启 | Python 循环 | 2.521824 s | 2.330999 s |
| 开启 | 完整进程 | 6.450428 s | 3.951647 s |
| 开启 | 宿主峰值 RSS | 2,950,168,576 B | 317,915,136 B |

默认关闭固定函数加速时，循环减少约 8.5%，完整进程减少约 39.2%。开启固定函数加速时，循环减少约 7.6%，完整进程减少约 38.7%。完整进程收益不能当作热循环收益；当前改进也不能被描述为已经接近 0.5 秒。

关闭固定加速的静态执行器三次循环为 2.333802 / 2.354303 / 2.315940 秒；开启时为 2.286242 / 2.330999 / 2.443437 秒。测量存在波动，不能从单个最快样本推断验收结果。此前 `python-comparison.json` 等中间报告有不同 LTO 设置，最终同构建对照以 `python-matched-*.json` 为准。

## 实际保留的热路径改动

- 操作尾部各自持有间接分派点，提前读取下一入口；条件未跳转路径直接消费显式 Next 边。
- 已驻留的整数、标量 FP 和普通加载目的直接使用角色寄存器。24 种移位/扩展准备形式在 lowering 时选择，去除执行时的类型判断。
- 整块预算守卫后按块边界结算退休数；helper、故障及系统调用按原始指令前缀精确恢复，短预算继续执行原始指令尾部。
- 私有匿名页使用按需分配的三层稀疏索引；未命中、文件依赖、共享、COW 写入、跨页及并行访问保留同步内存语义。
- 图按代码页聚合所需行证明。跨图桥接先检查缓存代次，再在汇编中消费当前观察周期已建立的 epoch / 行证明；证明缺失时在 C++ 就地重验。
- 成对 GP/向量访问、FP 位搬运和间接边有界多态缓存纳入原生路径，减少语义 helper 和完整状态导出。

整页提前比较的尝试已删除。三对交替测试中，整页版循环中位数 2.552879 秒，按需比较版为 2.321385 秒；不能因为减少校验调用次数就假定整体更快。仅改用直接角色寄存器的中间版也没有显示稳定的独立收益，最终数字包含全部保留改动，不能拆成未经测量的单项贡献。

## 0.5 秒目标与尚未实现的优化

独立 C API 诊断程序对源文件的临时副本插入输出标记，以 4096 指令预算记录边界累计数。两标记之间为 291,467,264 步，约 2.91 亿；边界采样及标记本身有额外指令，这不是原样程序的精确逐指令循环计数。原始性能测试始终使用未修改的源文件。

按这一数量级，0.5 秒需要约 5.83 亿客体指令/秒，当前混合负载约 1.25 亿/秒，还需约 4.7 倍吞吐。30,000,000 指令整数微基准很短，三次报告约 1056–2134 MIPS，不能外推为 Python 吞吐或 0.5 秒证明。

当前分配器仍是整图六个 GP / 八个向量架构寄存器角色缓存，**没有完整 SSA 值分配、全局 CSE、跨块值级 spill/reload 消除或大范围通用序列融合**。普通操作仍有静态 handler 分派。已有真实 CFG、循环和状态驻留并不等于任意程序的机器码 JIT，也不足以据此承诺剩余的约 4.7 倍。

## 正确性与构建

最终源码的 macOS Release CTest **41/41 通过**，含 **5,253 项可执行 ARM64 硬件 ISA 形式审计**。这是采样覆盖，不是穷尽 ISA。后端回归包含随机预算前缀、成对标量/向量访问、精确故障、角色交换、缓存回收、32 目标间接边、自修改代码、外部文件写入、代码行证明复用、权限、COW、共享及 FP 状态。完整运行日志已保存。Alpine 内部另有两项可选子测试因 rootfs 缺少 strace 和 liburing 开发文件而跳过，不能将 41/41 描述为所有可选功能均已执行。

iOS arm64 与 iOS Simulator arm64 静态库分别构建成功，部署版本 15.0、LTO 关闭；本轮未启动设备/模拟器、未构建 Flutter Runner，也没有重新打包 XCFramework。静态库成功不能代替平台运行验证。

最终 Node version/basic 在单 CPU、固定函数加速关闭和开启两组均通过，零 unsupported syscall。JS basic 使用现有 `--jitless` 探针，整进程分别为 14.292 / 14.354 秒；version 为 0.396 / 0.347 秒。它证明客体版本仍由 rootfs 提供，不代表 Node 已经获得强加速。workers/threadpool/network 和默认 V8 JIT 本轮未重新验证。

## 文件与证据

生产目录移除 `region.h`、`region_ir.h`、`region_compiler.cpp`、`region_engine.*`、`static_backend.cpp`，以及旧 `KernelEntry` / `bind_*` ABI、旧 region 测试和六个依赖该 ABI 的组件基准。更早的 interpreter/gadgets 路径也不在生产构建中。新增图、效果、优化、角色分配、lowering、执行帧、恢复描述、汇编和构建生成器，结构见 [静态执行器](../static-execution.md)。

最终 CLI 文件为 7,146,496 字节，对照为 21,115,360 字节；这是宿主 CLI 文件大小，不是 iOS 包体结论。汇编对象 __TEXT 为 4,367,508 字节。iOS / Simulator 静态 archive 分别为 16,265,416 / 16,220,656 字节，包含静态库符号及对象，不能直接当作最终 App 增量。

证据目录为 `tools/ios-runtime/arm64/build/static-execution-2026-11-06/`，包含：

- `python-matched-no-fixed.json`、`python-matched-comparison.json`：最终逐次输出、进程时间、峰值 RSS 和二进制 SHA256。
- `builds.json`、`summary.json`：源码/产物 hash、构建链接命令、编译器及中位数；冻结对照和新 CLI 仅作性能复测。
- `ctest.log`、`isa-audit.json`、`node-final.json`：最终测试证据。
- `ios-build.log`、`ios-simulator-build.log`、对应 `liboperit_arm64.a`：交叉构建产物。
- `proof-comparison.json`、`count-hot-loop.*`、`measure-*.py`、`execution-bench.log`：中间对照、诊断边界与复测工具。
