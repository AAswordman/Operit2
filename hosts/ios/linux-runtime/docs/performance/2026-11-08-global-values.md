# 2026-11-08：原生 SSA / 全局 CSE / 加载调度实验

实现已落盘，两项开关默认 OFF。局部微基准有收益，原样 Python 没有可靠的热循环收益；组合版完整进程变慢，因此没有默认启用。未构建或测量 iOS 真机/模拟器；下述结果只适用于 macOS 宿主。

## 实现范围

- `global_values.cpp`：GP/SP 与 NZCV 的 SSA 定义、显式 phi 输入、有界固定点值编号、跨块常量传播和纯整数公共表达式消除。复用仍可取得的架构寄存器结果，或删除结果已经相同的写入；没有通用 SSA 寄存器分配和 memory SSA。分析最多 1024 条指令、256 块、16 轮；更大的图保留原块内优化。
- 跨块事实生效的图仅公开根入口，避免把从前驱得到的假设错误用于任意外部入口。内部直接边仍连接，外部中间 PC 会构建自己的根图。预算后缀和异常恢复始终使用原始指令节点。BL 的推测返回边是未知输入，helper 未声明的效果保守失效。
- `static_lowering.cpp` / 汇编生成器：同基址、连续地址的两个独立普通 32/64 位加载，可提前第二次加载跨过最多三条纯整数操作，合并为宿主 LDP。检查原始依赖和 CSE 复制源；运行时证明串行、私有页、权限及完整页内范围，冷 TLB 补充后再次确认能力。持有的文件页锁先释放再回退。共享、并行、跨页与其他未证明情况按原顺序执行后缀，保留部分效果和精确退休。没有重排 store 或无守卫跨故障点移动访问。

这些是静态操作记录上的优化；没有运行时宿主机器码生成。Wasm 仍使用原来的共享块内优化，不使用 native SSA 或加载调度注解。

## 测量方法

Apple M5（10 核、16 GiB），macOS 26.6 / 25G72。Release/O3、thin LTO、诊断 OFF、Wasm OFF、固定函数替换关闭。原样 `benchmarks/python_loop.py` 100×100，SHA256 `736118e90c7989f0352d26bce340ef3118a4efcf7d6b465ba4a71a99849e5eec`，从同一个外部 Alpine rootfs 装载 `/usr/bin/python3 -B`；所有 checksum 均为 1267865，零 unsupported syscall、零固定助手调用。

最终两组实验都以同源码的两个开关 OFF 为冻结对照；每模式预热一次，交替顺序五对。编译、测试和采样不与验收计时重叠。宿主后台负载无法完全排除，因此同时保留配对胜出数和逐次样本，不将微小中位数差异当作可靠加速。不同表行属于不同轮次，不能串联百分比。

## 最终真实负载

| 配置 | 原样循环中位数：对照 → 候选 | 完整进程中位数：对照 → 候选 | 循环配对胜出 |
|---|---|---|---|
| 仅加载调度 | 0.519826 → 0.519805 s | 1.446485 → 1.431403 s | 3/5 |
| SSA/CSE + 加载调度 | 0.525021 → 0.524379 s | 1.440736 → 1.644581 s | 2/5 |

仅加载调度的循环差异约 0.004%，无法证明收益；组合版循环差异约 0.12%，且只赢 2/5 对，也不能证明收益。组合版完整进程增加约 14.15%。其全进程宿主指令中位数约 173.10 亿 → 208.45 亿，RSS 中位数约 586.51 → 634.04 MB；这些包括启动、构图、编译与退出，不能称为循环内部硬件计数。额外分析及根入口限制都有成本；这里没有进一步采样证明各自占多少。

单开 SSA/CSE 的早一轮隔离（以最初冻结原版为对照）为循环 0.521019 → 0.545339 秒、完整进程 1.441267 → 1.685873 秒，循环 0/5 胜。该轮早于最终加载守卫修复，不与最终两行拼成同场四配置排名。

## 有针对性的微基准

每次预热后执行 3 亿条客体指令，核对 GP、PC、NZCV，交替九对。CSE 负载刻意跨块重复表达式；加载负载刻意使用可合并的私有页访问。它们不能代表 Python、Node 或终端总体速度。

| 负载 | 中位数：对照 → 候选 | 吞吐比 | 配对胜出 |
|---|---|---|---|
| 跨块重复表达式（两项开启） | 0.155533 → 0.144517 s | 1.076× | 6/9 |
| 独立加载（仅加载调度） | 0.173685 → 0.117194 s | 1.482× | 8/9 |
| 独立加载（两项开启） | 0.153218 → 0.104635 s | 1.464× | 9/9 |

加载微基准的全程累计慢路径计数为 2；新增回归限制热循环的慢路径数，防止“所有执行都在正确的慢路径”掩盖快速路径从未生效。

## 失败原型与修正

第一版未限制 SSA 图规模，并对应用跨块事实的图收紧外部入口。五对循环中位数 0.525737 → 0.824103 秒，完整进程 1.462893 → 30.041777 秒，内存也大幅上升。该无界策略没有保留，最终增加了分析规模上限。

加载调度开发版还出现冷缓存无法补充、重复回退的问题；已修为复用原生 TLB 补充并重验私有页能力。第二次读取故障时的部分状态曾被外层失败发布覆盖，现于重抛前重载，回归比较第一结果、中间算术、故障 PC 与退休数。旧加载单开约 3% 退步的样本及早期微基准被后续修正覆盖，不作为最终性能结果。

## 验证与复现

两项开启的 Release 全量 CTest：44/44 通过，包含执行器、CPU 语义、ISA 硬件对照、代码失效、COW、并发内存及运行时。新增差分覆盖等值/非等值汇合、循环 phi、任意块入口、短预算、更改输入、ZR/SP、32/64 位、NZCV、call/return、随机整数 CFG；加载覆盖依赖、正负偏移、跨页、第二次故障、并行回退和 CSE 新依赖。默认关闭配置的扩展执行器回归另行通过。两项开启且诊断 ON 的扩展执行器回归也通过，包含最后增加的文件页锁释放与外部共享写入可见性用例。

```sh
cmake -S hosts/ios/linux-runtime -B /tmp/operit-global-on \
  -DCMAKE_BUILD_TYPE=Release -DOPERIT_ARM64_LTO=ON \
  -DOPERIT_ARM64_GLOBAL_VALUES=ON -DOPERIT_ARM64_MEMORY_SCHEDULING=ON
cmake --build /tmp/operit-global-on --parallel 6
ctest --test-dir /tmp/operit-global-on --output-on-failure
/tmp/operit-global-on/operit-arm64-global-opt-bench cse
/tmp/operit-global-on/operit-arm64-global-opt-bench loads
```

对照构建将两个开关均设 OFF，再通过 `tools/profile_execution.py --before ... --after ... --root ... --output ... --repeats 5 --warmup 1` 运行原样 Python；单项实验只开一个开关。不要与构建、其他基准或采样同时运行。

证据目录为 `tools/ios-runtime/arm64/build/global-optimizer-2026-11-08/`（本地构建产物，不提交二进制）：`loads-final/` 与 `combined-final/` 保存逐次 Python 输出、环境、二进制 hash 和 summary；`microbench.json` 保存微基准逐次输出与二进制 hash；`variants/` 保存冻结产物；`source-hashes.json` 保存实验实现源文件清单；`enabled-full-tests.log` 保存全量测试。早期失败轮次单独保留，不覆盖最终结果。
