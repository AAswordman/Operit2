# 2026-11-05：内存执行核的热路径搬运消除

> 历史记录：本页测量对应已删除的 C++ region/kernel 后端。当前执行器与结果见 [静态汇编执行器](../static-execution.md) 和 [交付状态](../delivery-status.md)。

后续区域编译和代码校验优化见 [代码页与编译复测](2026-11-05-code-pages.md)；本页保留前一轮内存核的同场结果。

本轮控制组是上一轮静态区域后端（SHA-256 以 `ee8e41d9` 开头），不是旧汇编解释器。候选组只改变内存执行核的慢路径内联边界、软件翻译条目布局，并补充组件基准和回归。

只构建和运行 macOS ARM64 Release CLI：`-O3 -DNDEBUG`，LTO / sanitizer 关闭；未构建 iOS、启动模拟器、使用设备或构建 Flutter App。原 `benchmarks/python_loop.py` 未修改。

## 实际问题与结构变化

1. 编译器把 `memory_slow`、`pair_slow`、`load_window_slow` 的同步、异常处理代码内联进热核。代表性的普通 64 位读取入口建立 240 字节栈帧，并先保存 128 字节寄存器，成功后再恢复 128 字节。guest 只读取 8 字节时，也会付出这些栈操作。
2. 三类慢函数改为 `[[gnu::noinline]]`，保留原有保证尾调用。快速命中直接检查、访问数据、跳至下一记录；失败才尾跳转至完整同步 / 故障路径。这改变实际生成的热路径机器码，不依赖 JIT 或运行时可执行内存。
3. `Translation` 的额外 32 位资格字段使条目扩大为 72 字节。将该字段改为容纳原有权限位的单字节，条目压回 64 字节并对齐至 64 字节，编译期断言其大小和对齐。每个 1024 项翻译表节省 8192 字节；索引由乘以 72 变成左移 6 位。
4. 将每次访问使用的映射 epoch 移到 TLB 前的表头。反汇编确认不再需要原先用于访问远偏移 epoch 的额外地址计算。

权限、精确页标签 / epoch、文件代际、跨页、COW、并行 / 共享同步、独占保留失效和可执行写入停止语义保持原有行为。

## 确认热点覆盖

使用单独的诊断二进制，对未修改的 Python 工作负载统计执行次数；该二进制含额外计数，**不用于性能计时**。此用例 `maximum_parallel_tasks=1`，计数器只用于这次单 vCPU 路径。

- 普通单值读取 76,652,901 次，其中 64 位读取 59,329,673 次。
- 普通读取快速路径失败 3,362,408 次，约 4.39%；此前约 95.6% 的快速命中也被内联慢路径的栈帧影响。
- 上一轮紧凑二读窗口仅执行 40,469 次。它无法代表整个读取类别，这也是只测两读窗口不足以判断内存大头的原因。
- 相邻且有直接结果依赖的指针追踪也有记录，但本轮没有为其增加新的解释循环或大量融合变体。

`access-profile.json` 中依次记录普通读取、普通写入、成对读取、成对写入、二读窗口；尺寸索引为 1/2/4/8 字节。

## 生成机器码核查

`hot-kernel-audit.json` 核对了普通读、普通写、成对读、成对写及二读窗口的代表性静态入口：五个入口均为 **零栈访问指令**。失败边是尾分支，热核没有进入 / 恢复慢路径栈帧。没有把冷函数的同步逻辑删除，也不据五个入口的核查声称所有编译器版本都会生成完全相同的指令序列。

原始汇编：`control/read64.s`、`read64-outline.s`、`read64-final.s`、`store64-final.s`、`read-pair-final.s`、`write-pair-final.s`、`read-window-final.s`。

## 同场实际工作负载采样

同一原始 Python 工作负载，两版交替采样，各三轮全进程及三轮延后窗口，间隔 1 ms。全进程挂接后最多采 5 秒；延后窗口从启动后 1.15 秒挂接采 1 秒，不能称为完全排除编译的稳态。

沿用并保存互斥叶样本分类器：编译和代码校验的子调用优先归于父类别，覆盖新增与已存在的热 / 慢内存入口；验证叶样本和等于主线程根计数。这里只报告主线程栈占比，不把它乘以进程 wall 冒充各部分的精确秒数。

| 类别 | 控制组全程 | 候选组全程 | 控制组延后 | 候选组延后 |

| region compilation | 20.21% | 23.53% | 10.00% | 8.98% |

## 证据与复现

仓库下 `tools/ios-runtime/arm64/build/memory-kernels-2026-11-05/`：

- `memory-comparison.json`、`memory-{control,candidate}-{0,1}.jsonl`：每轮秒数、次数、校验结果与正反序中位数。

- `ctest.log`：最终完整回归；`python-comparison.json`：同场五对原样用例计时及运行计数。

- `binaries.json`、`environment.json`：二进制 / 源码身份和 macOS Release 配置。
