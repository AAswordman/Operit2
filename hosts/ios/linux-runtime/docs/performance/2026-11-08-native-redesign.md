# 2026-11-08：原生执行路径重新分析

目标是不依赖运行时生成可执行机器码或 WebContent 的启动成本，优化通用 ARM64 客体执行。下述数字均来自 Apple M5 macOS，不能视为 iPhone 实测，尚未达到 5 倍目标。

## 缓存边界

构图遇到其他已缓存图的入口时停止投机发现，保留外部边，并通过已有链接路径验证目标的生命周期和代码。根入口仍照常构建。详细实现和自修改代码回归见 `block_graph.cpp`、`execution_engine.cpp` 和 `execution_backend.cpp`。

原冻结版本和缓存边界版本的五轮交替测试，Python 默认环境中位数：完整进程 1.4338 s 降至 0.7966 s，循环 0.5231 s 降至 0.5076 s，最大 RSS 586.5 MB 降至 139.7 MB。完整进程改善约 1.80 倍，循环约 1.03 倍。测试数据在 `tools/ios-runtime/arm64/build/runtime-redesign-2026-11-08/cache-boundary-round1/`。这是两版 Operit 的对照。

独立诊断运行中，编译基本块约由 48.2 万降到 8.5 万；诊断代码有额外开销，不用于验收计时。重新采样的三个非插桩运行显示，加载处理、页缓存地址翻译、块入口、跨图桥接和间接跳转都出现在主要热点中。调用栈采样是统计证据，不能将采样数当作精确的耗时占比。

## 加载内联实验：不保留

普通加载在页缓存命中时直接内联原有检查，缺页和其他慢情况仍调用原处理器。Release、Wasm/诊断/全局值编号/内存重排关闭，在相同 rootfs 上对缓存边界冻结二进制与候选版本预热后交替测量 9 对，checksum 均为 1267865。

| 指标 | 对照中位数 | 内联中位数 | 内联胜出 |
| --- | ---: | ---: | ---: |
| Python 循环 | 501.914 ms | 513.976 ms | 2/9 |
| 完整进程 | 786.824 ms | 797.894 ms | 2/9 |

完整进程包括进程启动；客体退休指令数会随 Python 的实际执行路径略有变化。本实验只覆盖一项 Python 负载，不能将结果归因于特定微架构因素。内联代码已移除。原始数据为 `tools/ios-runtime/arm64/build/runtime-redesign-2026-11-08/inline-load-round1.jsonl`；缓存边界版的三份采样文件为同目录 `cache-boundary-sample-{0,1,2}.txt`。

后续优化应针对多项叠加成本，评估更高效的执行表示及寄存器分配，同时维持图失效、精确预算和异常、自修改代码及并发语义。内联加载或单项局部改动的实验结果不能作为实现 5 倍加速的证据。

## 链接寄存器驻留

静态 ABI 将客体 X30 驻留在宿主 x3，并在每次 C++ 边界直接同步 shadow；块入口从 frame 读取代码 epoch 的预期值。扩展静态处理器的 GP 角色选择，保留零寄存器和 spill 的原有编码。未引入动态代码生成。

在同一台 Mac 上预热后，三种二进制轮换执行各六次；Python 循环中位数分别为：原六寄存器 506.627 ms、七寄存器 493.836 ms、实验性八寄存器 487.599 ms。七寄存器版本完整进程中位数由 782.917 ms 降到 768.775 ms。不同轮次客体实际指令数略有波动，不能直接解释为同一条指令的加速。

同轮 C 客体测试的六/七寄存器中位数：整数 121.071/120.252 ms、随机内存 56.752/57.914 ms、浮点 33.767/35.130 ms、调用 51.997/50.332 ms。随机内存和浮点存在回退，浮点样本波动较大；这些短测试不能推断所有应用都改善。可执行文件分别为 4,963,984、5,624,496 和 6,433,616 字节。八寄存器实验的代码增长和随机内存回退更大，未采用。原始数据在 `runtime-redesign-2026-11-08/resident-variants-round2.jsonl`，另有两轮两版本数据 `resident8-round1.jsonl` 和 `resident8-c-round1.jsonl`。

新增差分用例覆盖 X30 的 32 位自复制、跨图间接调用与返回，以及串行/并行、预算切点和原有故障边界。macOS 完整回归 44/44、诊断构建和全局值编号/加载调度开启时的执行器回归均通过，iOS arm64 静态库交叉编译通过；没有 iOS 真机测试。该方案只是有限进展，距离 5 倍目标仍远。

## Operit 构建期组合原型

为验证 Operit 自己的静态 ABI 增加了一个默认关闭的实验：诊断快照记录 lowering 精确选择的处理器变体；构建工具根据热点快照选取最多 256 段相邻变体，复制现有处理器汇编并去掉段内间接分派。生成的汇编在 App 构建时链接；运行时仅当已有操作记录的处理器入口逐项匹配时，才把第一条记录的入口替换为组合入口。操作参数仍从原记录读取。它不是完整的客体代码 AOT，也不针对动态加载的新客体生成机器码。

该原型延续原图的预算、代码校验和块入口；组合内每条操作仍让游标指向其原记录，因此访存失败从原慢路径恢复。强制命中真实组合的测试覆盖短预算、第二条成对加载故障及已执行代码修改后失效。诊断版独立运行的 Python 客体编译时安装了 9,772 处组合入口、动态进入 41,620,502 次；这些数字不是耗时比例或客体指令覆盖率。

macOS Apple M5，同一 rootfs、相同 guest 环境、预热后轮换九对，候选和控制二进制的所有 checksum 相同：

| 指标 | 控制中位数 | 组合原型中位数 | 组合原型胜出 |
| --- | ---: | ---: | ---: |
| 训练 Python 循环 | 540.775 ms | 505.522 ms | 9/9 |
| 训练 Python 完整进程 | 840.200 ms | 807.987 ms | 8/9 |
| 未训练 Python 工作段 | 329.353 ms | 323.924 ms | 9/9 |
| 未训练 Python 完整进程 | 818.526 ms | 809.278 ms | 7/9 |
| C 完整进程 | 545.917 ms | 544.841 ms | 5/9 |

训练循环约 1.07 倍，远低于目标。控制和候选二进制分别约 5.4 MiB 和 5.5 MiB；该实验仍有构图查找、每操作参数加载、频繁页保护检查以及块边分派，不能用它推断直接特化客体指令的收益或瓶颈占比。诊断插桩数据不用于计时。完整 Mac 回归 44/44 通过，启用该原型的 iOS arm64 静态库交叉编译通过；没有 iPhone 真机或正式 App 分发验证。

本实验以 `OPERIT_ARM64_SUPERBLOCK_PROFILE` 指向训练快照启用，留空时不生成、不链接组合处理器。生成器见 `tools/generate_profile_superblocks.py`，对照工具见 `tools/compare_superblocks.py`。冻结的两份二进制、训练快照、诊断数据、哈希和逐次样本在 `tools/ios-runtime/arm64/build/runtime-redesign-2026-11-08/profile-superblocks-round1/`。当前实现只是基础设施和受限实验，不应作为已达到 5 倍的交付；后续需设计具有精确内存故障及失效语义的直接寄存器/访存特化，并评估代码体积和未训练客体回退。

## 操作数特化实验

可选构建开关 `OPERIT_ARM64_SUPERBLOCK_SPECIALIZE` 在前述 profile 组合上进一步固化实际读取的操作数，并在安装时检查对应字段；纯计算序列可以将一个 shadow 槽暂存在宿主寄存器。它仍使用预先编译并签名的处理器，不在运行时生成机器码。按原训练快照生成了 256 个组合，其中 10 个满足保守的寄存器驻留条件。生成器拒绝不识别的 frame 访问、潜在别名、控制流和可能观察未写回状态的访存；诊断 handler 依据汇编约定保留 x14。此实验默认关闭，也不是客体二进制的完整 AOT。

Apple M5 macOS、相同 rootfs 和 guest 环境、每组预热并交替执行九对，各次 checksum 相同。两组对比是独立轮次，不能将两组中的中位数当成同轮数据：

| 比较 | 基线训练循环 | 特化训练循环 | 基线未训练工作段 | 特化未训练工作段 |
| --- | ---: | ---: | ---: | ---: |
| 不带组合的静态执行器 | 548.198 ms | 520.991 ms | 334.061 ms | 331.228 ms |
| 普通组合段 | 516.251 ms | 520.159 ms | 326.285 ms | 330.518 ms |

相对不带组合的静态执行器，训练循环约 1.05 倍；与普通组合段相比，本轮特化没有带来收益。未训练 C 程序的完整进程中位数在两组中均约 0.55 秒。不能据此认为单个子优化必然无效，也不能认为当前特化接近 5 倍目标。普通组合和特化的源码配置以及二进制不是同一份构建，具体命令和哈希见逐次记录。

特化构建的 macOS 完整 CTest 为 45/45；强制真实组合命中的执行器测试覆盖短预算、第二次加载故障和自修改失效；生成器另有七项针对性测试。这些测试不能证明全部 guard 组合和并发行为。启用特化的 iOS arm64 静态库交叉编译通过，但没有完成 App 链接或真机测试。原始数据在 `tools/ios-runtime/arm64/build/runtime-redesign-2026-11-08/specialized-vs-control-round1/` 及 `specialized-vs-generic-round1/`。尚无 iPhone 真机数据，不建议默认启用该实验。

## 构建期客体指令翻译实验

这是默认关闭的实验，不使用运行时可执行内存。`generate_guest_aot.py` 将训练快照中的客体指令序列翻译为构建期宿主 ARM64 汇编，随程序编译链接；不匹配的客体继续走现有静态处理器。支持无标志位更新的整数加减、逻辑移位、宽立即数，以及无写回的 1/2/4/8 字节整数访存。扩展版本还支持非标志位逻辑立即数和位域指令。访存沿用原有页权限、文件锁及故障慢路径；在可能故障的位置先提交 shadow 状态和操作游标。安装前按原始指令、图节点和操作边界匹配，初版拒绝任何包含常量折叠、dead-result 或 copy 重写的块；后续调整见下文。此阶段没有翻译控制流或完整 ELF，也不覆盖配对访存及 SIMD；构图、块入口、跨图分派仍然存在。

所有以下测量均为 Apple M5 macOS，不是 iPhone 数据。相同 rootfs 和客体环境，每组预热后串行轮换九对，checksum 一致。初始训练快照的 256 个热点产生 84 个受支持序列，控制与候选的训练循环中位数为 545.922/531.969 ms，完整进程 848.131/834.496 ms；未训练 Python 工作段 333.571/333.095 ms，C 完整进程 545.983/544.954 ms。约 1.026 倍的训练循环收益远非目标。

后续将采样表扩大到 8192 个站点、65536 组，得到 2292 个候选并按原筛选方式选出 1024 个；这是处理器入口采样而非客体指令覆盖率，且采样是在先前 AOT 构建上完成的。该次诊断保留 1,860,024 个样本、丢弃 10,198 个，AOT 动态进入 7,976,731 次；诊断开销不用于计时。

| 对照 | 训练循环 ms | 训练完整进程 ms | 未训练工作段 ms | 未训练完整进程 ms | C 完整进程 ms |
| --- | ---: | ---: | ---: | ---: | ---: |
| 静态控制 | 542.249 | 849.736 | 333.618 | 822.080 | 542.576 |
| 1024 序列 | 488.951 | 793.175 | 324.860 | 814.498 | 549.308 |

1024 序列版本训练循环约 1.109 倍、完整进程约 1.071 倍，二者均在 9/9 配对中胜出；未训练工作段及完整进程均为 7/9 胜出，C 完整进程为 3/9。与初始 84 序列版本另做同轮比较，训练循环为 535.893/483.301 ms，1024 序列 9/9 胜出。不同轮次数据不能相减归因。控制和扩大训练集的可执行文件分别约 5.4 MiB 和 5.8 MiB，构建期模式仍须为使用的客体提供训练数据，不能概括为对任意程序有同等收益。

加入逻辑立即数与位域后，候选数增至 2756，仍选 1024 个。与前述 1024 序列版本同轮比较，训练循环 483.545/479.672 ms（5/9 胜出），未训练工作段 326.108/321.972 ms（7/9），C 完整进程 544.301/548.845 ms（2/9）；不足以证明稳定收益。扩展仅保留在默认关闭的实验中，不作为性能结论或正式推荐配置。

强制确认生成代码入口的差分测试覆盖随机状态、短预算、32 位/SP、访存权限和故障、自修改代码以及文件截断；普通完整 CTest 46/46、生成器测试 11/11，另用大训练快照交叉编译 iOS arm64 静态库成功。普通 CTest 不强制命中，强制命中测试单独运行；未完成 App 链接、分发审核或真机测试。仍需更广泛的编码边界、并发文件锁和自修改差分验证。原始记录及冻结二进制在 `tools/ios-runtime/arm64/build/runtime-redesign-2026-11-08/guest-aot-memory-compare-round1/`、`guest-aot-large-vs-control-round1/`、`guest-aot-large-vs-small-round1/` 和 `guest-aot-bitfield-round1/`；大训练快照也保存在 `guest-aot-large-vs-control-round1/training-profile.json`。这些结果未达到 5 倍目标。

## 长序列与成对访存

后续实验增加了整数条件码更新，并允许在客体指令边界回写临时寄存器，以便翻译超过 8 条的连续片段。通过 `OPERIT_ARM64_GUEST_AOT_MAX_LENGTH`、`OPERIT_ARM64_GUEST_AOT_LIMIT` 和 `OPERIT_ARM64_GUEST_AOT_SCORE_LENGTH` 配置最大长度、数量及按预计减少的分派次数排序；默认仍为 8 条、1024 项和原排序。扩展还支持整数成对读写，包括有符号 32 位加载、前后索引和写回。成对操作一次检查完整访问范围，故障时仍从原静态操作精确回退；未翻译的控制流、SIMD 等仍使用静态执行器，不是完整 ELF 预编译。

使用上一节同一大训练快照，全部为 Mac 上预热后轮换九对的独立轮次。以下速度均为中位数，不能将跨轮中位数相减归因：

| --- | ---: | ---: | ---: | ---: | ---: |

长序列实验同时改变长度、候选数量和排序，不能把收益单独归于其中一项；成对访存扩展也改变了候选集。相应二进制大小依次约为 6.12 MB、7.38 MB、7.74 MB（十进制字节）。这不是对新客体通用加速的证明。

## 只读索引和 ELF 静态候选

将 AOT 候选索引从运行时构造的哈希表改为构建期生成的只读开放寻址表，仍逐项匹配原始指令及图节点，碰撞和最长优先顺序有单元测试。同一 profile 的 4096 项版本预热后交替九轮：训练循环对照 430.169 ms、候选 431.368 ms；完整进程分别为 726.737 ms、726.786 ms。未证明性能提升，也未见明显回退。数据见 `guest-aot-static-index-round1/`。

增加默认关闭的 `OPERIT_ARM64_GUEST_AOT_ELFS`，在构建期扫描 ELF64 AArch64 可执行文件段，拆成受支持的连续指令序列并生成预编译处理器；不支持的指令仍回退。可以单独使用 ELF，也可叠加 profile。它既不分析完整控制流，也不按 ELF 模块身份安装；安装依然要求运行时指令和图节点匹配，静态频率也不代表动态热点。实验混合排序直接相加 profile 样本数和静态出现数，两者量纲不同，不能视为可靠的热点估计。

用相同 Python 和 musl 文件、最多 32 条、4096 项，分别与只读索引 profile 版本在 Mac 上预热后交替九轮，中位数如下。训练 Python 工作段校验值为 1267865，其他负载也在各轮核对一致：

| 实验 | 对照训练循环 ms | 候选训练循环 ms | 对照未训练工作段 ms | 候选未训练工作段 ms | 对照 C 进程 ms | 候选 C 进程 ms |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 仅 ELF 静态排序 | 431.746 | 505.808 | 313.595 | 322.828 | 548.978 | 541.477 |
| profile + ELF 混合排序 | 437.873 | 439.074 | 319.118 | 315.121 | 549.345 | 549.434 |

仅 ELF 输入从 359,838 个候选中选择 4096 项，生成的汇编约 7.1 MiB，Mac CLI 约 7.0 MiB；混合输入汇编约 4.4 MiB、CLI 约 6.4 MiB。静态排序在训练循环中明显更慢，混合排序没有可确认的收益。这是两次独立轮次，不能直接相减推断效果；未训练 Python 脚本仍使用这些已知库。数据和冻结二进制见 `guest-aot-elf-only-round1/` 和 `guest-aot-elf-hybrid-round1/`。

## 优化块内的局部 AOT
