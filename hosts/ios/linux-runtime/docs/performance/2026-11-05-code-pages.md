# 2026-11-05：区域编译与代码校验复测

> 历史记录：本页测量对应已删除的 C++ region/kernel 后端。当前执行器与结果见 [静态汇编执行器](../static-execution.md) 和 [交付状态](../delivery-status.md)。

控制组为上一轮已完成内存执行核优化的静态区域后端。只构建 / 运行 macOS ARM64 Release CLI（`-O3 -DNDEBUG`，LTO 关闭）；未构建 iOS、启动模拟器、使用设备或构建 Flutter App。原样 `python_loop.py` 未修改。

## 实际删除和替换的路径

- 常量和 CSE 的两棵逐节点分配的红黑树，改为只存 SSA 编号的连续开放寻址表。
- 取指回调的 `std::function` 类型擦除，改为编译器模板参数。
- 状态绑定逐项扩容分配，改为 32 项临时数组收集后一次分配。
- 每区域临时整页数组、树节点及独有代码字节副本，改为最多八项引用表和共享不可变页快照；依赖保存只读数据指针与覆盖范围。
- 代码页快照的直接映射槽，改为按页地址处理冲突的哈希表。缓存最多保留 4,096 页，超过时冷重置；区域持有的快照不随之失效。
- 文件 / 并行校验的重复跨度检查，改为按页、快照身份、代码 epoch 和执行作用域复用 64 字节验证位图。串行缓存属于地址空间，并行缓存属于线程；命中不复制共享引用。

未命中仍通过 `PageAccess` 检查权限、文件边界、映射和锁。额外比较的行中字节变化时，再比较精确区域范围，区域外修改不会被误判为区域失效。没有删除同步、COW、文件截断、外部 mmap/pwrite 修改或自修改代码的语义。

## 独立组件计时

相同夹具、相同 host Release 标志。每个用例七个样本，正序 baseline→candidate，反序 candidate→baseline。编译每样本 8,192 个区域，包含结果释放；校验每样本 131,072 批 × 64 区域，共 8,388,608 次，包含每批 epoch 推进，不执行 guest 核。构造夹具和生成依赖在计时区间外。

旧校验基准独立保留生产函数原有语句，包括写回 `validated_epoch`，并以 `noinline` 保留一次函数调用；新基准调用生产 `CompiledRegion::validate`，双方不以跨模块 LTO 消掉这个边界。每个用例的前后校验和一致。

## 原样 Python 与回归

## 证据与复现

证据目录：`tools/ios-runtime/arm64/build/code-pages-2026-11-05/`。

- `control/` 冻结旧 CLI、归档、旧头 / 源码及对应基准源；`candidate-operit-arm64*` 为最终二进制。
- `component-comparison.json`、`components-*.jsonl` 保存所有秒数、次数、校验和与正反序结果。
- `python-comparison.json`、`ctest.log`、`profile/` 保存原样工作负载、完整回归与 12 份采样。
- `verify.py` 顺序执行组件、回归、工作负载、采样；`--components-only` 单独复测组件。
- `rejected-whole-page-validation/` 和 `rejected-instruction-bitmap-validation/` 是未采用的实验；`superseded-direct-mapped-snapshots/` 是冲突修复前的中间结果。它们没有混入最终表格。
- `binaries.json` 保存最终二进制身份；`environment.json` 保存源码身份和验证范围。
