# 2026-11-06：多 agent 采样与优化

验收目标为原始 `benchmarks/python_loop.py` 100×100 数学循环低于 0.5 秒，checksum 必须为 1267865。客体继续从外部 rootfs 装载 /usr/bin/python3，固定函数替换关闭；没有内置 Python、替换算法或运行时机器码生成。仅运行 macOS ARM64 宿主。

## 计时基线

宿主为 Apple M5，10 核。冻结生产对照 /tmp/operit-native-flags-control 在一次预热后，五次无采样循环时间为 1.330094、1.305164、1.291998、1.299073、1.349454 秒，中位数 **1.305164 秒**；完整进程中位数为 1.843231625 秒。0.5 秒目标在这份对照上尚未达到。历史约 2.3 秒版本保存在另一个证据目录，不能将此轮对照称为 Git HEAD。

证据目录：tools/ios-runtime/arm64/build/static-execution-multiagent-2026-11-06/。environment.json、baseline.json 和 baseline-summary.json 保存机器、二进制、客体 Python 与原始源文件的 SHA256、每次 stdout/stderr 和统计。验收源文件 SHA256 为 736118e90c7989f0352d26bce340ef3118a4efcf7d6b465ba4a71a99849e5eec。

## 优化依据

三次独立热区采样合计 3,368 个主线程样本。采样通过原始程序两个 CLOCK_MONOTONIC 客体调用限定窗口，不插入 Python 标记。attach 延迟和采样扰动意味着比例是统计定位，不能当作精确模块计时。

| 互斥分类 | 样本数 | 比例 |
|---|---:|---:|
| 原生控制流、分支、链接 | 794 | 23.575% |
| 原生访存 | 735 | 21.823% |
| 原生慢边界、重载、返回 | 533 | 15.825% |
| 代码校验 | 518 | 15.380% |
| 原生整数操作 | 381 | 11.312% |
| C++ 引擎及后代 | 182 | 5.404% |
| 其他运行时与系统调用 | 156 | 4.632% |
| 语义 SIMD | 34 | 1.010% |
| 原生 FP/SIMD | 24 | 0.713% |
| 显式状态传递 | 7 | 0.208% |
| 编译 | 4 | 0.119% |

旧 Return 符号覆盖了共享的访存回退尾部，不能把该符号全部归为真实返回。新诊断增加 MemoryFallbackRead/Write 别名供下一轮采样区分。

构建开关 OPERIT_EXECUTION_DIAGNOSTICS 默认为 OFF。诊断构建记录确切 handler 次数、分支条件、角色绑定选择、慢路径原因和代码比较长度；随机游标采样映射回 guest PC、原始指令和 lowered 序列。统计追加在执行帧 ABI 末尾，开关通过 PUBLIC 定义保证使用方布局一致。原始程序两个单调时钟的 resume/enter 快照差为热循环。

该差分中退休客体指令为 289,134,109，执行原生块 68,583,923，跨图慢速重验 2,934,144 次，桥接需要验证 56,380,623 个代码行；GP 桥接保存与重载各选择 47,536,331 个绑定。绑定数不是硬件实际 load/store 计数。约 26 个新图的诊断编译计时累计仅约 3.355 毫秒。Metadata 缓存没有碰撞或重复 fstat，因此不基于猜测修改哈希。

Xcode CPU Counters 的独立采样还显示：所选热循环内部窗口 1.8–2.9 秒，主线程按持续时间加权的 instruction delivery 为 41.715%，discarded 为 19.343%，processing 为 10.796%，useful 为 28.063%。该窗口是循环内部窗口，未与 guest 时钟逐条对齐；数据用于判断取指和分支压力。CPU Counters 运行产生 1.577885 秒循环时间，有采样扰动，**不用于性能验收**。原始 trace、XML 与计算结果保存在证据目录。

## 协作与复测

三个 agent 分别修改静态汇编/生成器、内存代码比较、图证明/链接。主线程整合、核查并串行执行构建、测试、诊断和计时。源文件冻结后才构建；所有重型运行不重叠。主线程另据 89 个 read 样本追踪到每时间片空 io_uring 完成队列的 EAGAIN 读取，给空队列增加发布状态，以跳过无意义系统调用。

工具 tools/profile_execution.py 可在任意已有生产 CLI 间交替测量同一源文件，保存逐次原始输出、hash、中位数、checksum 和目标判定。可选采样阶段独立执行，绝不混入验收中位数。

首轮执行器、代码校验、io_uring、异步完成、等待五项测试均通过；尚不能据此宣称完整回归通过。原始结果和冻结二进制分别保存在 round1、round1-libc、round1-libc-no-demand、round1-inline-no-demand 目录和同名 executor 文件中。

## 后续独立候选

已知节点直跳：Indirect/IndirectCall 在 link() 安装后，其目标恒为 PIC operation；Bridge 的目标恒为 select() 返回的 Block 头。利用这两个已证明的类型，省去读取 handler 再间接跳转，保留原 lifetime、epoch、预算与状态迁移守卫。五对循环中位数 1.236308 → 1.229088 秒，约 0.6% 变化，独立收益很小。该候选没有新增 handler 变体。

三层私有页索引改两层 16+20、惰性 mmap leaf 与 active 槽位清理的试验，在五对中为 1.238140 → 1.239366 秒，宿主指令减少而周期未降。**完整回退该实现和布局**，保留适配原三层结构的边界、native 读写、COW、权限撤销、并行切换、unmap/remap、共享与文件排除回归。

保留版再次采样 2,826 个热区主线程样本：原生访存 25.55%，另计共享 memory fallback 4.88%；控制流 22.68%，代码校验 14.12%，整数 13.16%，Slow/Reload 等边界 10.83%。反汇编将高频 Slow+40 和 Slow+72 分别定位到 mrs FPSR 与 msr FPSR；Reload+64 为 msr FPSR。下一项候选是专用 bridge proof 校验边界，并进一步检验浮点环境切换的实际成本。

专用 bridge proof 校验 ABI（round4）保留客体 GP/vector 驻留，只保存调用 C++ 必需的状态；验证失败转完整恢复路径，重新取得 native read guard 后复核 lifetime 和 epoch。五对中位数 1.244320 → 1.226117 秒。

延迟浮点环境切换（round5）只在首次原生浮点运算前安装 guest FPCR/FPSR，整数路径保持 host 环境；慢退出只合并 active 客体 FPSR，最终返回恢复宿主入口的完整浮点环境。新增测试覆盖宿主非默认 rounding/sticky flags、整数路径、浮点 helper、预算和访存故障。五对中位数 1.222682 → 1.202259 秒，约降低 1.67%；完整进程宿主指令中位数 21,670,547,749 → 21,567,410,486。两者都不是仅循环的硬件计数。

共享访存检查（round6）将 10,944 个重复站点的检查主体合并为读写 × 六种大小的 12 个静态叶入口，保留权限、跨页、三层页索引、file observation、PageMutex 和回退顺序。静态展开逐条比较一致；每次成功访问多一组 BL/RET。实际 __text 从 4,417,020 字节减到 3,446,780 字节，减少 970,240 字节。五对中位数 1.199179 → 1.144805 秒，约降低 4.53%；完整进程宿主指令 21,544,118,702 → 21,785,537,415 略增，周期 7,432,167,723 → 7,189,021,199 减少。这支持减少重复代码改善执行的假设，不把指令数下降当作唯一验收条件。执行器与代码校验测试通过。

所有时间均来自同场交替对照；不同轮次的绝对时间会随宿主状态变化，不能串联百分比充当最终对照。最终候选尚在继续优化；**0.5 秒目标仍未达到**。

## 保留版诊断与回归

round6 重新构建诊断版本，开启 bounded TOP=256，热区仍由原始两个 monotonic clock 边界确定。该次退休 287,174,319 条客体指令，handler 395,963,837 次，原生块 67,931,104 次；独立运行间客体路径会波动，不能要求与另一进程的退休数相同。诊断运行时间 5.487928 秒有计数和采样开销，不用于验收。

专用桥接校验调用 2,950,915 次，全部通过；通用 slow entry 395,986 次，其中 bridge_guard 仅 23 次。lazy_fp_enter 为 240,481 次；active 的 host 切换为 1,906,587 次，其中 Bridge 恢复 guest 为 1,666,106 次。专用 ABI 避免了热区约 295 万次通用 slow materialization。

热区 Prepare 为 9,775,442 次，选中的 GP spill 读取为 96,623,815 次、写入为 79,342,237 次；绑定计数不能当作实际硬件 load/store。新图编译 24 个、累计诊断计时 3.796 ms，优化重点应是热执行而非图构建耗时。

round6 保留源码构建全部宿主 target 后，串行 CTest **42/42 全通过**，包含 ISA audit、并发内存、精确状态、代码校验、共享与异步 I/O、rootfs/Alpine 测试；未使用设备或模拟器。完整日志为 round6-all-build.log 和 round6-all-tests.log。

## 删除重复验证与后续隔离

round7 将下一 handler 地址提前加载，没有可靠收益：五对仅两胜，配对节省中位数为 -10.845 ms，已完整删除。round8 将 ORR 左操作数为 ZR 的 MOV 别名直接降低为寄存器复制；W 自复制仍清空高 32 位。五对四胜，中位数 1.205293 → 1.173208 秒，配对节省中位数 24.777 ms，保留。

按用户要求隔离重复验证：round9 在图构建时预分组依赖、预计算 mask，并在已有 proof 命中时跳过 noinline 调用。五对零胜，1.178060 → 1.202153 秒；尽管完整进程宿主指令减少约 6.8 亿，周期上升。round10 仅保留预分组，五对两胜，配对节省中位数 -17.437 ms。两版生产实现均已删除，保留冻结二进制、patch 和测量。

round11 删除驻留代码页验证时不必要的 C++ 边界：CodeProof 在同步 PageAccess 内记录借用的页数据、快照、文件和页锁；汇编只在 serial scope 非零、代码与映射 epoch 均匹配、当前文件观测已存在且文件页仍有效时使用。比较前遵守 PageMutex 的 writer admission，失败或争用均退回原精确路径。只比较所需且尚未证明的 64B 行；通过后发布当前 scope 的证明。每次文件观测、外部代码变化、保护撤销和精确异常处理均继续有效。没有延长原文件观测周期。

该版同场五对全部变快：循环中位数 **1.187445 → 1.026222 秒**，配对节省中位数 161.223 ms。完整进程宿主指令中位数 21,863,635,860 → 16,887,873,531，周期 7,349,737,362 → 6,561,669,544；这些并非仅循环硬件计数。四项相关回归通过，新增文件桥接测试还覆盖外部 mmap 改写、执行权限撤销与恢复、截断后的精确 PC/退休数。**0.5 秒仍未达到。**

round12 的同集合 GP 寄存器排列改为静态 shuffle；720 种排列及预算/故障测试通过，但五对仅两胜，配对节省中位数 -7.391 ms，完整删除生产和对应候选测试。round13 将纯 LSL ADD 的 Prepare 合入 AddShifted，新测试通过；五对仅一胜，配对节省中位数 -23.636 ms，新增的 handler 集合及代码全部删除。

round14 将每操作的热记录从 48B 改成对齐的 32B，独立 16B 冷记录保存语义节点、精确退休前缀和诊断数据。控制边把退休前缀存入原本空闲的 b，Call 保留完整返回 PC，Bitfield 的两个 64 位掩码继续驻留热记录；Bridge/PIC 内联 16B 元数据保持已有 plan 偏移。冷 accessor 统一解释，诊断快照复制已解析的值以跨越图回收。总 payload 仍为 48B/操作，不能宣称总存储减少三分之一。

五对四胜，循环中位数 1.022456 → **1.000456 秒**，配对节省中位数 17.434 ms。完整进程宿主指令中位数 16,861,226,525 → 17,335,315,972，周期 6,578,659,307 → 6,514,220,637；RSS 中位数增加约 2.49 MB。高地址双 Call、每条 guest 前缀预算、Prepare 后故障和原执行器/ISA 回归通过。保留该候选。

最终诊断版本热循环退休 296,659,667 条客体指令、执行 410,837,878 次 handler。native proof 尝试 8,533,214 次、成功 8,483,579 次，仅 49,635 次进入 C++ 专用桥接验证；此前 round6 为 2,950,915 次。独立进程执行路径有波动，不能把两次绝对计数当成同一条指令轨迹。C++ validate_code_lines 热区调用降至 631,182 次（此前约 1,268 万个验证组），全局代码比较计数不包含 native leaf 的字节比较。hot-delta.json 同时保留两类数据，避免把移入汇编的工作统计成“零验证”。诊断运行 2.513796 秒不参与验收；新增图 26 个、诊断编译累计 3.104 ms。32B/16B 元数据快照无截断或失败。
