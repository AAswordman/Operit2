# 外部 root、数据迁移与历史性能

本文件保留原路径以兼容既有链接，原重复状态表已合入 [唯一最新交付状态](delivery-status.md) 和 [功能矩阵](completeness.md)。本文只维护迁移边界、测量方法及明确标注的历史记录；不再承担当前构建 / 测试汇总。

## 制备 root 与外部 root

`tools/ios-runtime/arm64/` 制备的是构建目录内的测试 / 打包 root，不是用户已安装数据。其架构与输入摘要标记用于限制工具覆盖、验证探针来源；制备过程的 staging 与 rename 也不代表用户 root 迁移已经验收。

运行时接受调用方提供的外部 Linux root，不要求外部目录带工具标记。CLI / C API 可在装载前绑定共享目录；权限来自宿主调用方。iOS 已有配置 UI、目录选择、bookmark、安全作用域与原位 rootfs 接线，具体运行 / 失败恢复证据见交付状态。不能将“原位使用外部 root”描述成必须复制为内部发行 root。

## 旧 x86 数据与 ARM64 边界

新 ARM64 root 与旧 `operit-ish/rootfs` 必须分开，不覆盖仍需保留的数据。x86 可执行文件、系统库、包数据库与原生扩展不能直接作为 aarch64 用户环境使用；需要重新安装 ARM64 软件。

迁移对象应区分用户文件、配置与工作区，再核对架构相关路径和二进制依赖。保留旧 root 直至用户数据、恢复与目标工作流验收完成。此处是迁移约束，不声明当前已经完成全部迁移或可安全删除旧目录。

外部目录引用需要保持配置 ID、目录授权与 session 的一致性；live 配置切换拒绝、关闭旧 session、bookmark 恢复、只读 bind 实际拒写均有源码 / 测试入口，最新执行层级以交付状态为准。后台、重启、授权失效与失败恢复仍需独立证据。

## 性能测量方法

`benchmarks/run.py` 对相同 Alpine 程序交替开 / 关固定助手，保留预热、重复次数、输出校验和原始样本。分别报告 guest 执行时间与含装载 wall，不把混合 instructions 计数当两种模式的同一工作量。解释器、宿主原生对照、模拟器和真机结果分别比较。

Worker 必须保留原始 guest 截止条件，并同时记录单 / 多核 host wall、CPU、平均用核与退出码。宿主并行活动不保证 wall 改善；最新数据只保留在交付状态。
