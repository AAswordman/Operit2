# 2026-11-02 架构与运行时自查

本次改为先建立独立指令清单和硬件差分，再按指令族实现，应用程序只用于验收。目标仍是完整的 ARM64 Linux 环境；当前没有达到整个 ISA、完整 Linux ABI 或高性能多核的完成条件。

## CPU 审计结果

第一轮以 1,142 种指令形式检查现有实现：619 种通过、523 种明确未支持。相同的 1,142 种形式在修复后全部通过，未通过的样本没有删除或转成跳过。

后续扩展至 **4,483 种形式、421,520 组输入记录、27 个测试分组**，全部通过 Apple ARM64 硬件对照。比较通用寄存器、向量寄存器、NZCV、FPSR 和访存区；包含寄存器重叠、边界值、可复现随机输入、六种 FPCR 模式，以及所有 256 个 FMOV 立即数编码值的五种标量/向量形式。

新增与扩展的实现按职责放在 `src/cpu/aarch64/`：

- `vector_arithmetic`：比较、乘加、差值、成对/减半、饱和与可变移位。
- `vector_unary`：绝对值、取负、零比较、计数、位反转和字节反转。
- `vector_widen`、`vector_narrow`、`vector_shift`：宽化、窄化、归约与普通/舍入/饱和移位。
- `vector_integer`：元素复制、标量 lane、字节提取和标量 ADDP。
- `vector_floating`：构建时静态汇编的向量浮点算术、比较、舍入与转换。
- `floating_context`、`vector_lanes`：共享的宿主浮点状态隔离和 lane/饱和/QC 语义。

另补充 SIMD literal load，并加入保留编码和不可用扩展的拒绝检查。浮点实现当前要求 AArch64 宿主；其他宿主仍报告不支持，不能伪称通过硬件验证。

**以上是可执行样本的结果，不是 ISA 覆盖百分比。** 尚未穷举全部合法编码、保留字段、寄存器、异常与内存边界。成对独占访问、indexed/doubling/polynomial SIMD、部分浮点转换、异常/信号等仍在 `tests/isa/architecture.json` 中列为缺口。

完整实际报告：`tools/ios-runtime/arm64/build/host/isa-audit.json`。版本化汇总与清单摘要：`docs/audit/2026-11-02.json`。

## 线程自查发现并修复的问题

1. **预算边界执行等待线程。** syscall 将线程置为等待后，预算可能恰好耗尽。之前下一次 run 可能直接继续该线程。现保留待调度状态，在恢复解释执行前完成选线程。
2. **按 API 调用而不是时间片切线程。** 调用者每次只给一条指令时，线程反复切换、清除独占监视器，原子循环可能永远无法完成。现将 4096 条指令时间片跨 API 调用保留，只在 syscall 或时间片结束后调度。
3. **未切线程也清除独占监视器。** 现在只有真正切换线程时清除，同线程暂停恢复不再无端破坏独占序列。

新增宿主任务测试和独立 Linux guest ELF，覆盖寄存器/TLS/信号屏蔽隔离、futex bitset/requeue/超时、轮询错误、单线程退出与整组退出，以及四线程共享原子计数和 clear_child_tid join。C API 还按每次一条指令运行同一线程用例，验证暂停恢复。

## Linux 环境审计与应用验收

- Python 3.12.15 的 JSON、数学、SHA-256、SQLite 和相关标准库导入在固定函数替换开/关两种配置下均通过；探针保存在 `tests/python/environment.py` 和 `tests/probe_python.py`。
- Node 24.18.1 版本启动通过，实际 JS/Worker/libuv 探针在标准错误流初始化时报 `open ENOTTY`，仍判失败。详见 `docs/node-probe.md`。
- 描述符的共享生命周期、epoll oneshot/close/reuse、阻塞 pipe/eventfd、宿主 SIGPIPE 隔离、信号交付、robust owner-death、网络、fork/exec/wait 等为已知未完成项。
- 全线程无限等待时，同步 run 仍可能无限等待；取消和宿主 wall-time 策略尚未实现。
- 当前调度是单宿主执行线程上的 guest 并发，未实现物理多核并行，也未完成性能验收。

## 验证

普通宿主 CTest 包含 CPU 编码检查、任务调度、硬件 ISA 差分、20 项 guest/C API 回归和 5 项 Alpine 集成用例。ASan/UBSan 使用独立构建目录运行同一套 CTest。

iOS device/simulator 静态库与 XCFramework、Swift Simulator 导入/链接另行检查；构建通过不能代替设备运行或产品接入验收。
