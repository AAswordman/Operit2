## 时间花在哪里

实际流程：Python 源码 → CPython 字节码执行循环 → Linux CPython/libm 的 ARM64 指令 → Operit 缓存块分派与静态指令处理器 → 宿主执行。两端同为 ARM64，也仍经过解释执行与寄存器/地址空间模拟。

导入后发出 READY，连续执行五轮相同负载，用 macOS `sample` 按 1 ms 间隔采样 4 秒。以下按主线程调用树划为互斥类别，共 3404 个采样；不把空闲 worker 计入分母，不重复累加父子调用。

| 路径 | 样本数 | 比例 | 内容 |
|---|---:|---:|---|
| 静态汇编指令处理器及进出 | 1406 | 41.30% | 指令分派、模拟寄存器、运算及该路径的内存检查 |
| 其他解释执行 | 581 | 17.07% | C++ 分派、普通指令处理及回退 |
| 内存执行 | 593 | 17.42% | 标量/向量加载存储、地址转换、页访问及相关文件检查 |
| 代码缓存校验 | 405 | 11.90% | validate_code、memcmp 及其文件/页访问子调用 |
| 专门浮点执行路径 | 107 | 3.14% | 浮点处理器；不等于用户算法的全部数学成本 |
| 调度、记账与其他运行时 | 312 | 9.17% | CPU 记账、事件轮询、调度、同步等 |

采样不是精确 CPU 周期测量，含系统调用等待。`thread_info`/Mach 调用在记账子树中出现，不能当作采样器开销删除。全局 self 样本中 fstat 为 128、TLS 地址查询为 107、Mach trap 为 155；这些已包含在表内，不能再相加。

这次带采样的五轮执行：启动到 READY 为 0.295 秒，循环各为 1.453、1.424、1.403、1.368、1.384 秒，最后 DONE 到进程退出为 0.038 秒。五轮共执行 1,502,674,935 条客体指令。另跑仅导入退出为 47,757,767 条，粗略扣除后每轮约 2.91 亿条，即每像素约 2.91 万条；独立进程的地址布局、哈希和计时调用有变动，因此该差值是近似值。

## 拷贝与冗余证据

使用仅注入诊断子进程的 DYLD interposer 统计 libc memcpy/memmove/memcmp。READY 经运行时转发至宿主 FD 后重置计数，日志必须存在 COUNTERS_RESET。Darwin 的 memcpy/memmove 可能指向同一实现，按合计与调用点解释，不按两个函数的分布解释。探针影响运行时间，只用其次数和字节数。

导入后的基线：浮点 scalar 写回 1,538,142 次通用拷贝，12,305,136 字节；代码 validate_code 比对 11,723,444 次，523,075,676 字节。没有观测到 257 字节及以上的 libc 拷贝。该结论不覆盖被编译器内联的复制，也不代表全部内存流量为零。

普通访存缓存宿主页指针；fork 共享物理页引用，写时执行 COW，没有发现该计算阶段持续整页深拷贝。逐条解释过程中仍有大量模拟寄存器读写和地址检查，零深拷贝不能消除这些开销。

浮点写回原先把 2/4/8 字节动态长度传给 memcpy。保留按位复制与高位清零语义，改为固定宽度分支后，该调用点消失。无探针交替测试（各预热一次、各五次）中位数：基线 1.342209 秒，固定宽度版本 1.307186 秒，观察到约 2.6% 时间减少；样本有波动，不据此承诺稳定收益。

存在可执行文件映射时，synchronize_shared 每个时间片推进 code_epoch，热点块随后比对内容。它保护外部代码修改和文件截断语义。整页快照复用原型虽通过初步功能检查，却使计算阶段比对量增至约 10.4 GB，并复制约 603 MB，已移除。条件写 FPCR/FPSR 的原型也未表现出收益，已移除。当前不放松内存权限、并发同步、文件截断或自修改代码语义。

## 热路径修复后的复测

此小节为删除分片缓存前的历史版本；当前实现见末尾。

在上述审计版本（已含浮点固定宽度写回）基础上，落地三处修复：

- 串行代码校验采用 4096 槽、每槽 64 字节的有界快照。每个 epoch 只刷新触及的短片段；重叠块复用 revision，没有内容变化时不再反复执行原来的整块 memcmp。槽冲突使用全局递增 revision 区分；并行执行保留原来的整块加锁比较。每个解释器增加约 352 KiB 快照及每块 40 字节 revision 元数据，不再采用之前已移除的整页快照原型。
- 已完成 COW 的私有文件页，当前执行 scope 已检查文件大小时可由静态 gadget 直接访问私有 RAM。scope 切换、fork COW、共享页、文件底层存储、权限或 epoch 不匹配仍先回退。没有删除文件截断检查。
- 仅一个可运行的普通任务、无定时器对象、且正在执行 guest 指令时，保留连续 CPU 记账区间，省去每 4096 条指令反复读取宿主线程 CPU 时间，并直接跳过无用的并行 batch 选择。syscall、多任务、实时策略、定时器和有限 CPU/RT 限额仍结算；API 返回时也结算。连续区间会包含此前 stop/start 间漏计的部分调度与轮询开销，不能承诺逐纳秒归属完全相同。

最终无探针计时，两边各预热一次、五轮交替运行相同 Python 负载：

|---|---:|---:|
| 循环耗时中位数 | 1.298184 秒 | 1.145850 秒 |
| 相对吞吐 | 1.000× | 1.133× |

时间减少约 11.73%，吞吐提高约 13.29%。全部校验和 1267865，退出状态 0、未支持 syscall 为 0。这是 macOS CLI 的小型计算负载，不能外推完整作图或 iOS 设备的加速比。

单独注入计数探针，从导入后的 READY 到退出，均确认 COUNTERS_RESET：

## 删除代码校验分片缓存

上一版本减少了 libc memcmp 调用，但引入每块逐片段遍历、快照刷新、revision 比对及二次字节比较。单独删除该层的五轮交替 A/B：1.158704 → 1.100594 秒，证明维护这层缓存对本负载不划算。现已删除 CodeLine、4096 槽快照、每块五个 revision 和 refresh_code_line，直接在原有页访问保护内比较缓存块的原始指令。每个解释器移除 352 KiB 快照，每块移除 40 字节 revision 元数据；不以 guest resident_bytes 冒充宿主总内存变化。

ReadGuard 保存获取时的 ThreadState 指针，解锁复用该指针；PageAccess 从已取得的 reader 状态判定是否已有 writer gate，不再重复获取 TLS；同一次文件 generation 判断只读取一次。并发门控与物理页锁仍保留。此前私有文件页直访与单任务记账优化继续保留。

最终相同 Python 负载、各预热一次、五轮交替执行：

|---|---:|---:|
| 循环耗时中位数 | 1.161388 秒 | 1.063516 秒 |
| 相对吞吐 | 1.000× | 1.092× |

耗时减少 8.43%，吞吐提高 9.20%；每次 checksum=1267865、退出 0、unsupported_syscalls=0。总吞吐改善不等于代码校验路径本身改善同一百分比。

代码校验采样占比由前次 17.54% 降为 14.02%。两次短采样不是精确周期统计，相对占比也不是绝对耗时变化。当前 libc 比对调用可以比快照版本更多，性能判断采用无探针计时而非调用次数。

曾验证以 vnode/kqueue 通知替代每时间片代码失效。最小宿主探针能收到 pwrite、msync 和 truncate 事件，却在已有共享 mmap 的两次直接写入后收不到事件；因此没有把该方案引入运行时，也没有删除对实际内容的校验。新增回归直接修改共享宿主映射且不调用 msync，确认 guest 能执行新指令，并保留权限和截断故障测试。最大 64 条指令块及串行/并行切换测试继续保留。
