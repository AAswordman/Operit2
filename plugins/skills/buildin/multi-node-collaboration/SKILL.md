# 多端 Agent 协作

你是当前会话的主 Agent，负责拆分任务、选择节点、派发子任务、跟进和汇总。每个子 Agent 使用独立的子会话，在分配的节点执行，仍由创建它的主 Agent 管理。主 Agent 可以同时处理自己的工作。

本 Skill 随应用自动安装，默认对 AI 隐藏，可在插件管理中开启 AI 可见性。协作依赖已安装并启用的子代理插件 `com.operit.subagents`，在主会话调用 `use_package({"package_name":"subagents"})` 激活工具。工具不可用时，报告缺少的插件或启用状态；Skill 本身不会安装插件。

## 选择节点与拆分任务

调用 `list_core_nodes({})` 读取 `currentNodeId` 和 `nodes`。从实际返回的 `nodeId`、名称、平台及可达性选择设备；任务目标必须满足 `reachable: true` 和 `canExecute: true`，仅提供转发的节点不能承载 Agent。使用完整 `nodeId` 派发，名称有歧义时先澄清目标。

按任务所需的数据、终端或设备能力分工，让相互独立的工作并行。每个子任务包含：目标节点 ID、目标、必要背景、输入及其来源节点与 VFS 路径、允许的修改范围、完成条件、需要返回的证据。同一文件或同一资源的修改要先划分所有权；有依赖的任务在输入就绪后再派发。

子 Agent 继承源会话配置，但不复制主会话消息历史，任务说明必须自包含。聊天与配置同步不代表设备外部挂载、终端会话或本地文件也已复制；需要跨节点读取文件时明确来源节点，不能把源设备的绝对路径当作目标设备路径。

## 创建并切换子 Agent

通过 `subagents:spawn_agent` 创建子任务，保存返回的 agent ID 与目标节点、分工的对应关系。它立即返回，任务在后台执行；派发其他独立任务后再等待。空间内最多同时运行 8 个子 Agent。

在 `task` 中明确要求子 Agent 自行切换。`switch_core` 作用于调用它的当前会话；主 Agent 为派发子任务而调用它，会切换主会话。每个子会话有独立 Binding，子 Agent 切换执行节点后仍保留原有父子关系和 agent ID。

派发示例，调用前把示例节点与任务内容替换成实际值：

```json
{
  "name": "服务器日志检查",
  "task": "你是主 Agent 的子 Agent。目标节点为 NODE_ID_FROM_LIST。先调用 list_core_nodes 核验目标可达且 canExecute=true；currentNodeId 不等于目标时，单独调用 switch_core({\"node_id\":\"NODE_ID_FROM_LIST\"})，结束本次工具批次。迁移续跑后再次调用 list_core_nodes，确认 currentNodeId 等于目标，再执行任务。目标不可用或切换失败时返回实际错误，由主 Agent 决定后续安排。任务：检查目标服务器指定服务最近的错误日志，定位失败原因。范围：只读，不修改配置或重启服务。背景与输入：这里填写服务标识、时间范围、已知现象及实际日志入口。完成后返回实际执行节点 ID、结论、日志证据和未解决问题。"
}
```

`switch_core` 返回成功标记后，运行时在工具边界提交 Binding 并续接到目标节点；标记本身不能作为已在目标运行的证据。子 Agent 应结束当前工具批次，续跑后核对 `currentNodeId`，再调用目标设备的工具。目标已是当前节点时直接核验并开始任务。节点不可达、无执行能力、切换或任务失败时如实回报，不在其他节点代做指定节点任务。

## 沟通、等待和收尾

| 目的 | 调用与处理 |
| --- | --- |
| 查看任务 | `subagents:list_agents({})` 返回当前主会话管理的子任务、状态和结果。 |
| 等待结果 | `subagents:wait_agent({"agent_ids":["实际 agent ID"],"timeout_ms":30000})` 等待任一所选任务的当前轮次结束。超时表示任务仍可能运行，继续等待同一 ID，不重复创建。多选返回后，继续等待其余仍运行的任务。 |
| 补充任务 | `subagents:send_input({"agent_id":"实际 agent ID","message":"自包含的补充任务或问题","interrupt":false})` 在该子任务轮次结束后发起下一轮。需要改变运行中的任务时显式使用 `interrupt:true`，它会等实际取消完成后发送新指令。 |
| 结束管理 | 收取结果并完成必要追问后调用 `subagents:close_agent({"agent_id":"实际 agent ID"})`。关闭会停止该子任务及其后代，保留会话历史；关闭后的 ID 不能继续发送。 |

子 Agent 在回复中向主 Agent 交付结果；主 Agent 通过等待结果和后续输入沟通。每轮要求子 Agent 返回实际执行节点 ID、已完成工作、产物的来源节点与 VFS 路径、验证证据、错误或阻塞。追加任务继续通过原 ID，要求子 Agent 每轮开工前核对当前节点。只有需要进一步拆分时才创建下一层子 Agent，并由它的直接父 Agent 管理。

主 Agent 根据各子任务的真实状态和证据整合结果，把跨节点依赖所需的上下文放进后续任务。收到节点错误时报告受影响的分工；不能把等待超时、取消、失败或仅发出切换标记描述成任务完成。
