# Edge 在设备空间中的职责

本文定义设备侧 Edge 的职责和与 Core、Host、ToolPkg 的边界。板卡运行与构建见
[ESP32 固件](../boards/esp32/README.md)，调试命令见
[ESP32 编辑器](../boards/esp32/editor/README.md)，插件接口见
[硬件 ToolPkg 接入](../../plugins/docs/edge-plugin-guide.md)。

## 节点形态与权限角色

Edge 是拥有自身原生业务的设备能力节点。固件负责硬件运行、本地交互及设备自身业务，
可通过设备空间提供原生服务，也可使用其他节点的能力。屏幕、麦克风、GPIO 和模型请求
都是设备可以选择实现的能力，不是成为 Edge 的必要条件。

硬件 Edge 节点与名为 `edge` 的权限角色分别表达实现和授权：

| 项目 | 硬件 Edge 节点 | 完整 CoreNode |
| --- | --- | --- |
| 应用组成 | 原生设备应用、Edge Services、共享节点服务与 Host | OperitApplication、Core 路由、业务服务与 Host |
| 设备配置和自身状态 | 设备应用负责，按需持久保存 | 对应业务 owner 负责 |
| Agent / ToolPkg 执行 | 当前 ESP32 不提供 | 取决于实际服务和当前授权 |
| 共享业务副本 | 当前 ESP32 不提供 | 双方具备存储授权且实际提供 Core 存储服务时交换 |

内置 `edge` 角色具有设备查看和 `runtime.execute`，没有默认 `network.relay` 或
`storage.provide`。权限本身不会安装 Core。执行目标同时要求 profile 声明 Core
且具有 `runtime.execute`；当前 ESP32 的 `coreVersion` 为 `None`，不能作为
`switch_core` 或聊天 Binding 的执行目标。完整 Core 也可以被授予 `edge` 角色。

## 发现、配对与成员资格

Edge 和 Core 复用共享 Peer runtime 的身份、验证码配对、加密会话和连接恢复，
通过 Host 提供 TCP、串口等载体能力。固件不另建 Edge token 或第二套配对协议。

配对证明两台设备之间的直接信任；加入 Space 另需申请和明确审批。配对成功不表示
成员资格、执行授权或业务副本同步完成。Edge 可以发起申请，也可以展示并处理共享
服务分配给本机的审批。初始化、申请、取消和审批恢复使用共享服务的持久记录，
UI 只保留有界展示状态，不生成第二份审批权威。

| 操作 | 对直接配对的影响 | 对空间的影响 |
| --- | --- | --- |
| 配对 / 重新配对 | 成功确认后建立或替换凭据 | 不自动授予成员资格 |
| 本机解除配对 | 删除本机对应的直连授权 | 不等同于退出或移除成员 |
| 主动退出空间 | 保留直接配对 | 回到本机单设备空间 |
| 隔离设备 | 保留成员和配对，策略阻止连接与中转 | 解除隔离后才允许恢复连接 |
| 移除设备 | 按共享控制服务处理撤销与凭据遗忘 | 移除成员；再次接入走标准配对和加入流程 |

离线时的撤销、重新接纳和旧移除消息按共享控制日志及配对世代判断，不能由固件
根据一次网络错误自行清空身份或重写权限。旧管理员不可达时，设备可以经本地确认
主动退出；未入空间的远端不能通过 RPC 代替用户重置设备。

## 受限设备的实现边界

Edge 和 Core 共享 Peer、Space、路由和权限语义。每个节点根据本地已接受的空间控制状态
校验请求；Core 不接管设备的授权，本机审批也由共享 Space 服务执行。

[受限设备的空间与展示链路](core-entry-protocol.md)说明控制状态发布、报文边界、
聊天展示契约和模拟器限制。设备只保留运行所需的节点状态、原生资源与有界展示窗口。
完整聊天、工具参数、工具结果和执行状态留在 Core；投影通过中立契约交换普通展示文字。

## 本地数据与配置交换

Edge 可以保存身份、密钥、配对、必要的成员/权限/审批状态，以及设备原生配置和资源。
不具备 `storage.provide` 不会禁止本地存储、设备运行或自身 preference 同步。

设备 preference 按 `(spaceId, nodeId)` 隔离，通过同空间控制通道交换。每个键按
逻辑版本和写入节点合并，删除保留标记，避免离线旧副本复活已删除配置。当前上限为
24 个键、6144 字节完整明文状态；删除标记也占用有界状态。本地加密保存，合并失败
不得发布部分状态。交换重新检查当前成员、隔离、撤销及空间范围。

设备配置交换不复制聊天数据库、附件、插件包或业务文件，不推进业务同步时钟。
显示远端聊天所需的按需读取和有界 RAM 缓存也不构成业务副本。
`storage.provide` 与实际 Core 存储服务共同决定是否参与完整业务复制。

## 原生服务与 Host 边界

设备应用注册自己的原生 Call、Watch / Stream 和 Push / ReverseStream 端点，
并处理设备本地输入。宿主通过 `Tools.device(nodeId).transport` 或小型配置入口
`Edge.execute` / `Io.execute` 访问。能力、数据格式和动作由端点声明；无对应端点
时返回明确错误。拥有通用通道不表示设备支持任何 Core 工具或任意宿主函数。

- Host 实现平台 I/O、存储、HTTP、显示和调度；共享 Peer runtime 管理认证与连接。
- Edge Services 和固件拥有设备行为；`EdgePeerRouter` 接入共享 runtime，处理本机
  Target 请求及规定的空间控制入口，不承担完整 Core 的 Binding 分派。
- `operit-edge-contract` 只共享地址和 DTO；`operit-proxy-edge` 封装类型化调用。
- 固件不运行宿主 ToolPkg。配置 ToolPkg 负责编辑和保存，停止或卸载后不影响已经
  保存的设备行为。需要持续宿主计算时，使用单独的处理插件或已有 Core 服务。

通道保留标准 Link 的顺序、完成、取消和错误语义。取消等待不代表撤销已提交的硬件
动作；超时或断线后不得自动重放非幂等动作。不要增加按传输类型分叉的业务协议。

## ESP32 的两条聊天路径

### 设备独立模式

保存有效的 `chat` preference 后，设备通过 Host HTTP 直接请求配置的模型服务。
无需 Core 常驻或 Binding；其他成员掉线不清空同空间的本地对话。当前上下文仅在
RAM 中保留最多 8 条消息、6144 字节文本，单条最多 2048 字节。

模型配置和上下文都受当前空间约束。切换空间后先退役旧上下文，再校验新配置；
即使两个空间配置相同，或者新配置无效，也不沿用旧空间的会话。旧空间已提交的
HTTP 请求可能完成，但其迟到结果不能进入新会话。固件无法读取空间或配置时也会
退役当前上下文并显示错误。重启保留配置并开始新的对话。

### 远端 Core 模式

未配置独立模式时，Edge 可通过已准入的入口 Core 使用现有 Binding 路由。
Core 创建聊天、选择执行节点、保存历史和推进 Agent；Edge 只保存选择的聊天 ID、
有界显示窗口和本次交互状态。订阅和发送需等待显式创建确认，不靠读写隐式创建 Binding。

同空间短暂断线保留聊天选择，入口或认证会话变化后恢复订阅；换空间或显式退出、
解除配对时清理旧查看状态。恢复显示不自动重放发送、新建聊天、插件测试或硬件动作。
插件列表与固定诊断也在 Core 执行，`"edge": {"exclusive": true}` 只是展示分类。

## 检查与文档分工

重新配对及旧控制消息；修改配置时验证并发合并、删除、范围隔离和写入失败；修改
Core 使用路径时验证订阅恢复、迟到结果隔离和非幂等动作不重放。
