# ESP32 模拟器 Rust 堆分配实测（2026-10-27）

这份报告按真实分配/释放记录给出字节数。分项统计对应同一次总堆峰值，所有分项互斥且可以与分配器总账核对。

## 测量条件

- 运行完整 `simulator-space.test.mjs`，覆盖配对审批、聊天、插件调用、断线重连、90 行历史分页、取消及进程重启。
- Rust 堆固定 262,144 字节，仍使用原来的 `linked_list_allocator`。每次分配记录请求大小、实际 `heap.used()` 增量、指针及调用栈；释放时撤销原始分配。
- 总占用刷新峰值时，复制当时仍存活的分配计数。表中的峰值是同一时刻的占用，未累加各模块在不同时刻的最大值。
- 调用栈地址使用本轮匹配的 EXE/PDB 离线解析。按分配点向上的第一个项目源码帧分类；这表示直接分配来源，跨模块传递后的对象所有权需要另行分析。
- 诊断表位于独立静态区，写文件直接调用系统 API，未从设备堆分配统计元数据。统计区、诊断工具自身和线程栈均不计入下表。
- Windows 调用栈采样会增加执行栈消耗，诊断运行临时使用 64 KiB 的主/异步/阻塞栈。此表属于该诊断运行。随后已逐字节恢复源码和测试断言，在原有 16/24/20 KiB 栈限制下复验完整场景。
- 本轮启用 release 行号调试信息，优化级别仍为 3。结果属于 Windows 模拟器的 Rust 堆，不能直接当作真机整板 RAM。

## 删除 Peer 中转链路与模拟器标准输入 IPC 后的验证

本次直接替换旧实现，保留标准 Link Call / Watch / Push 编码、认证、心跳、授权重检及事件顺序：

- 删除 `peer/live_channel.rs`。同一个连接读取任务完成解密后的心跳处理与响应关联，请求进入独立执行端。删除原有 inbox、搬运读取任务及重复终止状态。
- 删除 `StoredMessage::Value / Encoded` 双表示及 `peer/compact_message.rs`。队列统一保存 `EncodedMessage<T>`；通过共享的常量栈字段扫描器读取路由字段，执行时才展开业务负载。Call 请求与响应的队列交接保留原字节分配。
- Watch 队列保存编码后的事件，消费时解码；移交事件时不再克隆值树。调度失败和连接结束共用同步终止步骤，释放等待者及队列。
- 编辑器与模拟器通过一个经过启动令牌认证的 loopback TCP 连接交换现有 JSON 命令。删除 stdin、异步标准输入阻塞中转及其多层缓冲；接收端使用 1 KiB 帧缓冲。输出字节仅在一次发送期间持有。
- 状态响应改为类型化 `SimulatorState`，借用设备标识及发送回执，直接序列化；删除仅为输出构造的外层动态 JSON 树。
- 网络启动、命令执行、响应序列化保持清晰的执行阶段。mDNS 首次初始化在独立的主栈生命周期中完成；命令完成后才进入序列化，删除额外响应包装造成的约 3 KiB 轮询帧叠加。所有阶段仍使用原定主栈预算。
