# 受限设备的空间与展示链路

ESP 是共享节点架构中的对等节点。Peer 负责身份、配对和会话，Space/Router 负责成员、
权限和路由，Host 提供网络、存储和调度。设备可审批加入自己的空间，也可经正常配对与
审批加入另一个节点的空间。展示投影不改变上述权威关系。

## 控制状态

请求沿 Peer 会话进入 Router，由当前空间及已接受的控制状态验证。控制状态按存储 Host
共享：新建查询句柄不重新装载和重放整份日志，也不复制整份权限集合。

控制投影发布版本和控制日志修改版本共同标识快照。控制操作追加、导入、移除与日志重写
使快照失效；重放完成后再次检查源版本，发布一致的已接受状态。撤销必须被后续请求观察到。
审计和完整历史导出仍读取历史，它们不位于每次权限查询的路径中。

空间传输按明确的版本、节点身份和接收报文上限校验。Core 和 Edge 都提供 manifest
与逐条权限导出，申请方使用同一收集器验证不可变操作、完整清单和最终版本，再按
共享权限规则导入。加入路径只接受明确支持分页的目标，不再请求完整历史快照。
协议错误直接结束本次交换，不能把网络错误解释为新的权限。

出站建连和配对确认由 Host 异步任务执行，空间工作任务只等待结果。配对确认前和凭据
提交时分别校验原事务的当前授权。身份、凭据和带版本的配对记录直接解码目标类型，
不先构造完整 Preferences 树；审批记录的 envelope 与 source 分阶段解码，再通过所有权句柄跨阶段传递。申请准备阶段结束并
释放来源、目标快照及其工作 Future 后，只携带 request ID 进入响应阶段，重新读取持久记录。Peer 按报文 `body.result` 的结构字段区分请求和响应，字段扫描
使用固定栈，不先尝试错误类型的完整解码。

## 审批的证据与投影

控制日志是成员与权限的权威。申请保存的不可变来源快照是命令证据；列表、审核分配、
状态轮询和诊断只读取 `ConsentProjection`，保留请求身份、来源世代、成员 ID 与决策事实。
投影直接从编码记录读取所选字段，不先解码完整记录再丢弃证据。命令输入的已认证路由
使用固定栈扫描器定位，退出路由解析后再独立解码业务字段，避免通用值树再转换成命令。审核收件箱只保存分配
投影；实际领取审批时才从网关取得证据。不存在的记录集合读取为空，不创建 schema 文件。

首次提交携带来源证据，网关确认后持久标记 `submitted`。此后用 `joinStatus(requestId)`
查询状态；网络错误结束本次调用，不切换成重新提交。状态回复只含请求事实和批准后的
成员投影，不回传来源快照、profile、拓扑或控制历史。网关不保存第二份 accepted 快照；
批准回复按当前日志中的精确 admission、审批者、来源成员集合和当前权限生成。

申请方收到批准投影后，独立收集当前目标控制日志并验证 admission，再导入成员与展示
资料。投影不能代替授权。审批按领取证据、生成决策和完成提交分阶段执行，证据在生成
决策阶段结束时释放，完成阶段只持有决策结果。无变化的状态轮询不重写原始申请。

控制导出同样区分 manifest 和操作页。快照头只读取版本和数量；分页先完成不可变记录
校验与版本关联，退出扫描后才解码选中的操作。manifest 的摘要覆盖原始完整字节，包含
未知字段；重名操作仍需证明内容一致，游标和版本不匹配直接报错。
分页结束时校验成员、控制日志版本和退出事实，展示 profile 与拓扑取最后一次头部投影。
链路测量时间更新不改变授权，不能让正常测量更新打断权威导出。

## 聊天展示

生产依赖由中立的 `operit-edge-contract` 描述。设备不依赖 Core 的聊天、工具或 proxy 实现。

Core 从标准消息 parts 投影普通正文、图片占位文字和工具公开名称。Thinking、ToolResult、
工具参数、调用 ID 和工具执行状态不进入设备展示数据。工具名称是普通文字，不是私有
控制字符、XML 或设备端状态机。

窗口用时间戳和 UTF-8 字节游标分页，并按请求的字节数与行数限制。订阅在 Core 侧处理
源流、保存点和回滚，输出有界的追加或替换文字。设备不保存源流修订历史。流完成时校验未闭合的语义内容，历史 Markdown 也先由 Core
解释；无效语义以窗口错误返回，不能直接展示其中的工具载荷。另一设备产生
的消息通过同一聊天窗口订阅进入展示；断线恢复重开当前窗口，权限仍由共享 Router 校验。

## 存储与执行

固件和模拟器共用 PackedRuntimeStorageHost 与记录/快照 codec。NVS 和桌面文件只是载体；
压缩、记录大小、逻辑容量和事务发布顺序共用同一实现。桌面原始文件 API 在独立载体栈上
执行，压缩、解析和空间处理仍在设备任务栈内。载体不解释空间或聊天业务。

模拟器的 Rust 堆是固定 256 KiB arena，分配器不能向系统追加容量。主任务栈 16 KiB，
异步工作栈 24 KiB，阻塞工作栈 20 KiB，均由保护页限制。栈映射与 Rust arena 分开计量。
这些是模拟器预算，不是 ESP-IDF、Wi-Fi、TLS 或 C UI 的整板内存测量。C/Wasm 展示层报告
自己的静态缓冲与栈。编辑器每次状态查询只构造一份聊天展示快照，标题和空状态文字
复用该快照；错误对象保留代码、消息和调用位置，不在设备错误路径强制解析完整回溯。
桌面 Tokio 的事件批量受到限制，避免默认桌面驱动缓冲挤占设备预算。
HTTP/WebSocket 网络任务在设备兼容配置中进入同一个 24 KiB Host 异步工作线程，
不能额外创建四个桌面网络运行时，也不能绕过设备栈预算。HTTP 连接建立以同一
executor 中的独立任务执行，避免 reqwest 连接器与请求处理叠加调用栈；请求取消或
连接超时会丢弃并终止连接任务。Peer Call 的传输阶段也由 Host 异步任务承接，
调用者取消即释放排队或进行中的工作，原始请求关联与权限校验保持完整。

模拟器发现服务绑定明确的本机接口；直接启动且启用发现时必须设置
`OPERIT_SIM_DISCOVERY_IP`。编辑器使用与广告地址一致的接口。桌面 mDNS 原始事件收集
使用独立的 128 KiB Host 载体栈和一个无 I/O 驱动的服务工作线程，业务仍在设备预算内。
发现依赖 polling 2.8.0 的桌面事件批量固定为 16，来源归档经 SHA-256 校验后在隔离目录
生成，所有 Rust 分配仍计入同一 arena。运行 Cargo 前执行项目虚拟环境中的
`edge/boards/esp32/editor/prepare-simulator.py`；编辑器和内存检查会自动准备。

监听只执行一次 Host bind。配置端口 0 时使用 Host 实际绑定地址；不扫描其他端口，也不
根据错误字符串猜测是否应重试。

## 验收

独立子进程检查堆分配成功/拒绝、各任务栈的正常执行/保护页越界。真实 CLI 与模拟器
检查配对、设备空间审批、请求与交互、其他设备更新、撤销和重启。单元测试通过不能代替
完整交互。集成测试在每次读取设备状态时校验固定预算与零分配失败，并汇总跨重启
堆峰值；独立 HTTP 聊天还验证 CLI 退出及设备重启后的行为。模拟器通过不能声明真机全部场景已通过。
